## 三、怎么跑

```bash
# 1) 解析：旧 SQL → articles.jsonl + 媒体清单 + 报表（不动数据库）
~/py-tools/bin/python tools/migrate/legacy_extract.py parse \
  --sql "/path/to/gxhczx_db_2026-09-05_02-30-02_mysql_data.sql.gz" --out tools/migrate/out \
  --expect-rows 21363 --expect-max-id 64092 \
  --deleted-from "/path/to/gxhczx_db.sql"
# --expect-*：导出完整性自检，行数或最大稿件号对不上直接退出
# --deleted-from：拿一份更早的导出做基准，产出 deleted_ids.txt（旧站已删稿件号）

# 2) 抓图与视频：抓回本地并回填清单（4 并发、超时 15s、重试 3 次、间隔 200ms）
#    改从服务器拷文件的走下面第 2b 条，不抓网
~/py-tools/bin/python tools/migrate/fetch_media.py \
  --manifest tools/migrate/out/media_manifest.csv --base http://www.gxhczx.gov.cn

# 2b) 离线核对（服务器拷贝场景，不联网）
~/py-tools/bin/python tools/migrate/fetch_media.py \
  --manifest tools/migrate/out/media_manifest.csv --verify

# 3) 渲染：清洗正文 + 按清单改写媒体地址 → articles.final.jsonl
~/py-tools/bin/python tools/migrate/legacy_extract.py render \
  --in tools/migrate/out/articles.jsonl \
  --manifest tools/migrate/out/media_manifest.csv --out tools/migrate/out

# 4) 入库：先干跑看报告，再提交（--archive-ids 把旧站已删稿件转 archive）
php tools/migrate/legacy_import.php --in tools/migrate/out/articles.final.jsonl --dry-run \
  --archive-ids tools/migrate/out/deleted_ids.txt
php tools/migrate/legacy_import.php --in tools/migrate/out/articles.final.jsonl --commit \
  --archive-ids tools/migrate/out/deleted_ids.txt

# 5) 发布与 301
php backend/bin/publish.php --out=backend/storage/publish
php backend/bin/redirects.php --out=backend/storage/publish --check=backend/storage/publish

# 6) 对账：逐栏目证明“一篇没少”（有缺失时退出码为 1）
~/py-tools/bin/python tools/migrate/reconcile.py \
  --sql "/path/to/gxhczx_db_2026-09-05_02-30-02_mysql_data.sql.gz" \
  --db backend/storage/hechi_zx.sqlite --out tools/migrate/out/reconcile.csv
```

产物都在 `tools/migrate/out/`（已 gitignore）：`articles.jsonl`／`articles.final.jsonl`（入库字段）、`media_manifest.csv`（`url,target,status,bytes,sha256,error`）、`mapping_report.csv`、`unmapped.csv`、`deleted_ids.txt`／`deleted_summary.txt`（旧站已删稿件与分类小计）、`side_tables.json`、`stats.json`／`render_stats.json`、`report.txt`、`imported_ids.txt`（入库回滚清单）、`archived_ids.txt`（转归档清单，回滚时改回 `public`）、`reconcile.csv`（逐栏目对账）。上一版（4/28 口径）的产物完整保留在 `tools/migrate/out-20260428/` 供对拍。

## 四、字段映射

`rd_news` → `cms_article`（另写 `cms_article_channel` 主归属、`cms_article_image` 图集、`cms_attachment` 附件）：

| 旧字段 | 新字段 | 规则 |
| --- | --- | --- |
| `ID` | `article_id` | 沿用旧库号（与 301、旧链接同号） |
| `Type` | `channel_type` | 同号栏目的 `type_code` |
| `Title` | `title` | 去标签、压缩空白 |
| `Word` | `content_html` | Python 初清 + `HtmlSanitizer` 终清（唯一清洗出口） |
| `Title1` | `summary`（Type=202 时 → `role`） | 202 先取 `Title1`；主站这批领导稿 `Title1` 为空，则取 `Edit` 里的职务字样（旧站模板就是 `Edit LIKE '%主席%'`，含主席／秘书长／主任／党组） |
| `Title2` | 不迁 | varbinary 存的总期号 |
| `Pic` | `thumb` | 抓取成功的改写为站内地址 |
| `From` | `source` | 去掉“河池日报 2026/1/2 1 版”这类日期版面尾巴（范围内 1,618 条） |
| `Author`／`Edit` | `author`／`editor` | 原样 |
| `Time` | `published_at` | Asia/Shanghai |
| `Num` | `views` | 原样 |
| `Audit` | `status` | 1→`published`，0→`draft` |
| `Order` | `cms_article_channel.sort_no` | 仅 Type=202（领导）沿用；旧站其余栏目按时间倒序，不迁 |
| `Hot`／`Top` | 不迁 | 旧语义是“进首页模块／热点”，与新站按栏目置顶不同，避免排序错乱 |

清洗规则：去掉 `font`／`span`／`o:p` 等标签与内联样式、折叠空段落与连续 `<br>`、`&nbsp;` 归一；正文里的图片、视频（44 处 `<video>`／`<source>`）与附件（2 条）按抓取结果改写为站内地址。**本次范围内 0 篇含 `<table>`**，因此没有为表格扩大清洗白名单。
