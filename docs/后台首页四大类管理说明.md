# 河池政协网 · 后台首页四大类管理说明

> 编制日期：2026 年 9 月 11 日
> 改动范围：后台侧栏（首页管理分组）与 `/admin/nav`、`/admin/slides`、`/admin/sections`、`/admin/banners` 四个页面；首页数据组装；首页横幅位与导航条的前端渲染
> 迁移：`database/migrations/{sqlite,mysql}/003_home_sections.sql`
> 验证：`node tests/admin-check.mjs` 186 项、`node tests/api-check.mjs` 47 项、`node tests/check-pages.mjs` 19 例（接口模式 20 例）、`node tests/order-e2e.mjs` 19 项，全部通过

## 1. 为什么要按四大类重排

后台原来只有“栏目管理”和“稿件管理”两个平铺入口，而编辑实际是**照着首页做内容**的：哪条上头条、哪个栏目出在首页哪一块、横幅什么时候换。改版前的问题是：

1. 首页 21 个数据块整块存在 `cms_home_block` 里，是阶段 A 从旧站抓下来的**静态快照**，后台没有任何入口，改不了；
2. 首页顶部的 18 个导航入口、首屏 6 张轮播、7 处横幅图，全部写死在 `frontend/home/index.html` 或快照里；
3. 稿件的“置顶”勾选框写的是 `cms_article.is_top`，而列表查询**根本不读这个字段**，勾了没有效果；
4. 在栏目管理里调栏目顺序，首页导航条纹丝不动（两者数据不同源）。

现在按编辑的视角把后台分成四类，每类对应前台一块区域，数据都取自同一个稿件库。

## 2. 四个大类与前端区域

侧栏结构：**概览 / 首页管理（树形，默认展开）/ 稿件管理 / 用户管理 / 操作日志**。四个大类收在“首页管理”这个分组里，分组标题点一下可以折叠；当前页在树里高亮，面包屑也带上“首页管理”这一层（如“概览 / 首页管理 / 其他栏目”）。没有 `home.manage` 的角色看不到这个分组，只有 `channel.manage` 时分组里只保留“全部栏目”。

| 后台页面 | 对应前台区域 | 数据来源 |
| --- | --- | --- |
| 导航栏目 `/admin/nav` | 首页与内页共用的顶部导航条（18 个入口） | `cms_home_block` 的 `nav` 块（仍是一份可编辑列表，不按栏目自动生成） |
| 头条轮换 `/admin/slides` | 首屏大图轮播（现有 6 条） | `cms_home_slide`：可从已发布稿件引用，也可手工登记外链条目 |
| 其他栏目 `/admin/sections` | 首页正文的 13 个内容模块 | `cms_home_section` 配置 + 稿件表实时组装 |
| 站内横幅 `/admin/banners` | 首页 7 个固定图片位 | `cms_home_banner`，槽位 `hero-1`／`hero-2`／`body-1`…`body-5` |

## 3. 数据模型

迁移 `003_home_sections.sql`（SQLite 与 MySQL 同构）新增：

| 表／字段 | 用途 |
| --- | --- |
| `cms_article_channel.is_top` | **按栏目置顶**：首页模块与栏目页列表共用一套顺序 |
| `cms_home_section` | 模块配置：`section_key`、`label`、`scope_json`、`page_size`、`group_by`、`more_url`、`status`、`sort_no` |
| `cms_home_slide` | 头条轮换：`article_id`（0 表示外链条目）、`title`、`summary`、`image_url`、`link_url`、`sort_no`、`status` |
| `cms_home_banner` | 站内横幅：`slot_key` 唯一，`title`（alt）、`image_url`、`link_url`、`status` |

`scope_json` 三种写法：`{"channels":["306"]}`（指定栏目）、`{"parent":"601"}`（一级栏目含全部子栏目）、`{"tabs":[{"channel":"904","label":"市政协动态"}]}`（按子栏目分标签）。

`bin/seed.php` 会把现状固化为初始配置（13 个模块、6 条轮播、7 个横幅槽位），并且**只在目标表为空时写入**——表里一旦有数据就说明后台已接手维护，重复跑 seed 不会覆盖编辑改过的绑定、头条与横幅。

## 4. 首页怎么组装

`HomeRepository::blocks()` 是首页数据唯一出口，接口 `/api/v1/home` 与静态化发布器共用它，所以接口与静态快照永远一致。规则：

1. 先取 `cms_home_block` 的原样快照作为基线；
2. 对 `cms_home_section` 里已上线的模块，按 `scope_json` 找栏目，取这些栏目下**已发布且公开**的稿件，排序为“置顶在前 → 栏目内排序值 → 发布时间”；
3. 不足 `page_size` 时，用同名快照里的历史条目补足（同 id 不重复；库内条目缺图／缺日期时用快照字段补齐）——这样编辑发稿立刻出现在首页最前，同时不会因为稿件库里暂时没有内容而让某个模块变空；
4. `slides` 改由 `cms_home_slide` 提供：引用稿件的条目取稿件标题／摘要／链接，图片缺省取稿件缩略图或正文首图；**稿件一旦撤回、下线或删除，该条自动从轮播里消失**；
5. 新增 `banners` 键，按槽位返回条目数组。

“在本栏目置顶”写到 `cms_article_channel.is_top`，三个入口都能操作：稿件编辑页的复选框、稿件列表**按单个栏目筛选**时的 ↑ ↓、以及“其他栏目”页每个模块表格里的 ↑ ↓ 与置顶按钮（后两者操作完跳回原页面）。**取消置顶时按发布时间落回它原来的位置**，不会把一篇旧稿顶到栏目最前；跨过置顶稿调整顺序会提示先取消置顶。

## 5. 四个页面怎么用

- **导航栏目**：每行改显示名称与链接、勾“隐藏”、按 ↑ ↓ 调顺序；右侧显示该入口指向的栏目与稿件数，点栏目号直达该栏目稿件列表。导航条顺序即前台从左到右的排列，改动实时生效。
- **头条轮换**：上方是首屏效果预览，缩略图可直接左右拖动调顺序（松手即保存）、点图在新窗口预览前台页面、点图片右上角红叉并确认后删掉该条；“从已发布稿件里选”默认列出最近发布的稿件，也可按标题检索，点标题可在新窗口预览前台页面、点“加入轮播”即引用；“手工新增外链条目”填标题、链接、摘要、图片。列表里每条可上移／下移、上线／下线、删除，展开可改标题、摘要、链接与图片。
- **其他栏目**：页面最上面是**栏目索引**，把全部 43 个栏目按“首页模块绑定的栏目／未进首页导航的栏目／只在首页导航里”分三行列出来，点栏目名跳到本页对应位置（模块卡片或下方清单那一条；只在导航里的栏目本页没有内容，点开进它的稿件列表）。每个模块把当前显示的稿件**按头条轮换那样的表格列出来**——缩略图、稿件（标题＋稿件号＋时间）、栏目、状态（已发布／已置顶）、操作（↑ ↓ 调栏目内顺序、置顶／取消置顶、编辑、前台），多标签模块按标签分表；表下若有未入库的旧快照条目会单独说明。展开“改绑定与显示条数”可改模块标题、绑定方式与栏目、首页显示条数（1—30）、上线／下线。页面下方列出去向不在首页导航里的栏目。
- **站内横幅**：7 个槽位各一张卡，可上传新图或填写图片地址、改链接与 alt、上下线；位置不增删（位置一变前台版式就得跟着改）。

**改前先确认**：这四类页面的改动都是保存即同步前台（前台读实时接口），所以凡是会改变前台显示的提交——导航保存（含隐藏）、轮播上线／下线／删除／编辑保存、模块保存（改绑定、条数、上下线）、置顶／取消置顶、横幅保存（换图、改链接、上下线）——都会先弹一次确认，文案写清这一下会造成什么；点取消什么都不发生。上移／下移与预览区拖动排序这类“只换位置、随时可逆”的操作不弹，免得每挪一格都要确认一次。确认由后台脚本接管，脚本没加载时按原方式直接提交。

权限：四类页面统一用新增的 `home.manage`（管理员默认拥有，可在“用户与角色”里授予其它角色）。所有改动写 `sys_operation_log`，操作日志页已为这些动作补了中文名。

### 改完前台没变？先分清用的是哪套数据

首页数据有两个来源，**它们不会自动互相同步**：

| 来源 | 什么时候用 | 后台改完会不会自动变 |
| --- | --- | --- |
| 实时接口 `/api/v1/home` | 站点页面默认走这条（`php -S` 起的 8080 就是） | 会，刷新即见 |
| 静态快照 `frontend/home/data/*.json` | 阶段 A 的样例数据；`python3 -m http.server` 这类纯静态预览、GitHub Pages 预览 | 不会，它是一份固定样例 |
| 发布产物 `backend/storage/publish/data/*.json` | “立即发布全站”的产物，供 Nginx 直出用 | 不会，要点一次“立即发布全站”重新生成 |

判断当前页面用哪套：在站点页面控制台执行 `SITE_DATA.mode()`，返回 `api` 是实时接口、返回 `static` 是旧快照；地址栏加 `?api=1` 可强制走接口、`?api=0` 强制走快照。四个后台页面底部也常驻这条提示。

## 8. 未做与限制

### 已有库怎么升级

新库按 `php backend/bin/migrate.php && php backend/bin/seed.php` 正常跑即可。**已经在用的库**不要重跑 `seed.php`（那会把栏目与稿件按快照重新覆盖一遍），改用：

```bash
php backend/bin/seed.php --home-only
```

它只做两件事：执行 `003_home_sections` 迁移、回填首页模块／头条轮换／横幅的初始配置，不动栏目与稿件。

没跑之前**站点不会报错**：`HomeRepository` 检测到三张新表不存在时会退回“纯快照”组装（与改版前完全一致），首页四大类里的“导航栏目”页照常可用，另外三页会显示一页说明提示先执行迁移。

1. **不做定时生效**：头条与横幅只有上下线，没有生效／失效时间；定时发布属阶段后期的增强。
2. **模块骨架固定**：不新增前端没有的模块，也不改模块在首页的上下顺序（顺序由前台版式决定）。
3. **导航条不自动生成**：18 个入口里含外部链接与聚合页（县区政协、政协文史馆），继续人工维护。
4. **不做新建／删除栏目**：仍与重构前一致，只能改、排序、上下线。
5. **快照兜底是有意的**：阶段 A 的首页快照里有一部分稿件并不在稿件表中（图片新闻、时政要闻等模块的历史条目），所以组装时保留兜底；随着编辑在对应栏目里发新稿，这些历史条目会自然被顶下去。
6. **`more_url` 只存不生效**：模块的“更多”链接前台仍按原规则生成，字段先记录下来备用。
