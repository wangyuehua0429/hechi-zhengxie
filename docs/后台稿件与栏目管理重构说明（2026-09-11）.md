# 河池政协网 · 后台稿件管理与栏目管理重构说明

> 编制日期：2026 年 9 月 11 日
> 改动范围：`/admin/articles`（稿件管理）、`/admin/channels`（栏目管理）、`/admin/article/{id}`（稿件编辑）、`/admin/channel/{type}`（栏目编辑），以及后台公共外壳
> 涉及文件：`backend/templates/admin/*.php`、`backend/public/assets/admin.css`、`backend/public/assets/admin.js`（新增）、`backend/src/Admin/{Article,Channel}Controller.php`、`backend/src/Repository/{Article,Channel}Repository.php`、`backend/routes/admin.php`
> 验证：`node tests/admin-check.mjs` 133 项、`node tests/api-check.mjs` 41 项、`node tests/check-pages.mjs` 19 项，全部通过

## 1. 这轮要解决的事

在**不动现有功能**的前提下，让后台操作更直观。落到编辑身上是四个具体的不顺：

1. 想知道“我现在看的是哪一批稿”，得先看稿库、再看关键词、再看栏目导航条——三处筛选分散在页面上中下三段。
2. 想改一篇稿，得先在最右边的操作列里找到那一行的小字“编辑”；标题本身点不动。
3. 想批量处理（一次提交十篇、一次通过十篇），只能一篇一篇点。
4. 想调栏目顺序，得进编辑页手填“排序（越小越靠前）”的数字，填完也不知道自己排到了哪里。

## 2. 改动前的实测情况

以下都是重构前在本机 `php -S` 起后台、用 1440×900 视口实测到的现象（截图见本轮 QA 记录，未入库）：

| 位置 | 实测现象 | 依据 |
| --- | --- | --- |
| 稿件列表 | 稿库导航条、关键词表单、栏目导航条是三块独立区域；43 个栏目的导航条占 5 行，是全页最高的元素 | `articles.php` 旧版依次输出 `.vault-nav` → `.filters` → `.channel-nav` |
| 稿件列表 | 表格第一列是稿件 ID，标题不可点，入口在最右一列；每行动作是“撤回…”“编辑”这类文字链接，窄列里会折成两行 | 旧版 `<td><?= $id ?></td>` 与 `.row-actions` 的 `flex-wrap: wrap` |
| 稿件列表 | 无排序、无每页条数、无批量操作、分页只有上一页／下一页 | 旧版 `ORDER BY a.published_at DESC` 硬编码、`PAGE_SIZE = 20` 常量 |
| 稿件编辑 | 表单从标题一路堆到正文，保存按钮在最底部；附件、正文插图、回收站入口在保存按钮之后，要滚过 18 行正文才能看到 | 旧版单列布局 |
| 栏目管理 | 43 个栏目平铺一张表，“一级栏目”这一列每行都在重复；无检索；稿件数是纯数字，不可点 | 旧版 `channels.php` |
| 栏目编辑 | 排序只能填数字，页面上没有任何“当前排第几、前后是谁”的信息 | 旧版 `channel_edit.php` 只有 `sort_no` 输入框 |

## 3. 改了什么

### 3.1 稿件管理（列表）

1. **筛选收进一块面板**：稿库、栏目、关键词、排序、每页条数现在同处一个 `.filter-panel`，中间用虚线分隔；页面标题下方给一句自然语言摘要，如“共 406 篇稿件 · 已筛选 栏目：市政协动态　稿库：草稿”，后面跟“清除筛选”。
2. **表格改成内容优先**：第一列是稿件（标题即编辑入口，副题、稿件号、置顶、作者退到次要行），然后是栏目（一级名 + 子栏目名分两行）、发布时间、状态（徽标 + 最近动作合成一列）、操作。稿件 ID 从第一列退到次要行。
3. **新增排序**：发布时间／最近更新／稿件号 × 升序降序，界面上是一个下拉，表头“发布时间”也带升降序切换。
4. **新增每页条数**：20／50／100。
5. **新增批量操作**：勾选行后可批量“提交审核／审核通过／退回／撤回／重新发布／恢复”。动作清单按当前账号的权限位生成，备注（撤回原因／退回意见）在选中需要备注的动作时出现；**“移入回收站”不进批量**，仍走单篇确认页。
6. **分页补全**：首页／上一页／页码窗口／下一页／末页 + 跳转到第 n 页。
7. **空状态给下一步**：没有结果时提示换稿库或清除筛选，而不是只写一行“没有符合条件的稿件”。
8. **行内危险动作改为指向确认页**：列表里的“移入回收站”现在是 `/admin/article/{id}/delete` 确认页，不再直接 POST 流转接口。

### 3.2 稿件编辑

1. **两栏布局**：左侧是内容表单，拆成“基本信息／发布设置／摘要与正文”三块卡片；右侧是常驻侧栏，放稿库流转、稿件信息（稿件号、栏目路径、创建与更新时间、前台入口）、附件、正文插图、回收站。
2. **保存条吸底**：`.form-actions` 粘在视口底部，改完正文不必再滚到底找保存。
3. **正文预览**：点“预览正文”在文本框下方渲染正文（纯文本按空行分段、HTML 原样呈现），预览走 `sandbox` iframe，脚本不执行；旁边实时显示“正文约 n 字”。
4. **快捷键**：Ctrl/⌘+S 保存；表单有改动且未提交时，离开页面会提示。
5. 顶部补“前台预览”“返回列表”，并显示当前稿库徽标。

### 3.3 栏目管理（列表）

1. **按一级栏目分组**：43 行平铺改成“一组一个表体”，组头写一级栏目名与概况（子栏目数、稿件条数、上线／下线数），组内顺序就是前台导航顺序。
2. **组内上移／下移**：每行两个按钮，直接与相邻的同级栏目交换排序值，不必再进编辑页填数字；组内第一个的“上移”、最后一个的“下移”自动置灰。
3. **可检索**：按栏目名、栏目号或 URL 标识筛选（服务端 `?q=` 生效，页面加载后另有一段脚本做即时过滤，无脚本时按“筛选”按钮一样能用）。
4. **可跳转**：稿件数链到该栏目的稿件列表，“前台”新开该栏目页，“编辑”进栏目详情。
5. 顶部补统计数据：栏目总数、已上线、已下线、栏目稿件数合计。

### 3.4 栏目编辑

1. 新增“在导航里的位置”卡片：同一级栏目共几个、当前第几个、前一个与后一个分别是谁，并可在此处上移／下移。
2. 表单拆成“名称／版式与状态／栏目简介”三块，排序值收进“高级：手动指定排序值”折叠区。
3. 顶部补“前台栏目页”“返回栏目列表”。

### 3.5 公共外壳与渐进增强

1. 新增面包屑（`概览 / 稿件管理 / 编辑稿件`），由布局按 `$current` 与页面标题推导，控制器不必逐个传。
2. 侧栏增加“查看站点前台”，顶栏保留退出；新增“跳到主要内容”链接。
3. 新增 `backend/public/assets/admin.js`（零依赖、`defer` 加载）：批量选择与全选半选、栏目即时筛选、正文预览、字数统计、快捷键与未保存提醒。**不加载脚本时以上功能全部降级为不可见或走原有表单**，原有操作一个不少。

## 4. 新增的后端能力

| 能力 | 落点 | 说明 |
| --- | --- | --- |
| 列表排序 | `ArticleRepository::adminPaginate()` | 排序字段走白名单（`published_at`／`updated_at`／`article_id`），模板传什么都不会拼进 SQL |
| 列表分页大小 | `ArticleController::index()` | `size` 只接受 20／50／100，其它值回落默认 |
| 批量流转 | `POST /admin/articles/bulk` | 逐篇复用 `applyFlow()`：状态机、数据范围、权限位、备注校验、操作日志与单篇完全一致；单次上限 100 篇；只处理白名单动作 |
| 栏目上移下移 | `POST /admin/channel/{type}/move` | 只交换相邻两个栏目的 `sort_no`，其它栏目顺序不变；越界给出“已经是这一组的第一个／最后一个”提示 |
| 栏目分组与检索 | `ChannelController::index()` | 内存分组与过滤（43 个栏目的规模足够），不新增 SQL |

两条约束写进了代码注释：排序字段白名单、批量动作白名单。两者都是“模板／请求传什么都不会越界”的写法。

## 6. 未做与已知限制

1. **正文仍是 HTML 文本框**：本轮只加了预览与字数统计，没有引入富文本编辑器（属阶段 C 的“正式模板与富文本”待办）。旧文是 `<div>/<p>` 结构，直接上富文本存在往返丢格式的风险，需要先定编辑器与清洗规则。
2. **批量不覆盖“移入回收站”**：删除是不可逆感最强的动作，保留单篇确认页。
3. **栏目不能新建／删除**：与重构前一致，仍只有改。
4. **拖拽排序未做**：用上移／下移代替。拖拽要引入脚本库或自研指针事件，且键盘可达性更麻烦，收益不足以在本轮铺开。
5. **不加载脚本时**：批量勾选、全选、即时筛选、正文预览与快捷键不可用；筛选按钮、上下移、流转按钮等表单路径都照常可用。
6. **前台地址**：栏目“前台”按钮指向 `/channel.html?id={栏目号}`、稿件“前台预览”指向 `/detail.html?id={稿件号}`，这是本机 `backend/public/router.php` 与当前前端目录的地址形式；换成静态化发布目录后应改为 `/channel/<slug>/`，届时只需改模板里的这两个链接。
7. **视觉细节**：本轮以结构与交互为主，未逐项核对行高与间距；后续若统一换 UI 皮（见 [开源选型说明](开源选型说明.md) 第 3.2 节），本轮的类名与 `data-*` 钩子可以原样沿用。
