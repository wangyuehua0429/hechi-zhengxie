# 旧站图片线索与拷贝清单

> 用途：迁移入库的 4,203 篇稿件里有 1,151 篇正文仍指向旧站 `uploadfiles/`，本地没有这些文件。
> 本文把“图片在哪儿、本地有什么、还缺什么、怎么最快补齐”一次说清。
> 编制日期：2026 年 9 月 14 日；口径与迁移流程见[旧库迁移说明](旧库迁移说明.md)。

## 一、结论

1. **文章图片（`uploadfiles/`）只在旧站服务器上**：`/www/wwwroot/gxhczx.gov.cn/uploadfiles/<年月>/<文件名>`。本地这份备份里没有这个目录，宝塔的每日任务也只备份了数据库、没有备份网站文件。
2. **图片清单是齐的**：旧站页面与旧库正文里合计出现 16,975 个不同的图片路径，其中本次迁移要用的 2,406 个已写成媒体清单（`media_manifest.csv`，由 `parse` 产出）。
3. **抓网这条路已经放弃**（2026-09-14 实测）：随机 40 个地址、4 并发跑一轮，5 分钟只落盘 39 张，还有地址卡在 15 秒超时×3 次重试上，全量要数小时且不稳定；抓取脚本与抓取记录已按决定删除。现网图片本身仍可访问（抽 3 个地址返回 200），但补齐一律走服务器拷目录。

## 四、两条补齐路径

### 路径 A：从服务器拷目录（推荐）

服务器上的站点根目录是 `/www/wwwroot/gxhczx.gov.cn`（来自宝塔 vhost 配置 `vhost/nginx/gxhczx.gov.cn.conf` 的 `root` 指令），所以图片在：

```
/www/wwwroot/gxhczx.gov.cn/uploadfiles/<年月>/<文件名>
```

按清单只挑需要的目录即可，规模可控：

```bash
# 在服务器上：按 copy_dirs.txt 逐个目录打包（只打本次迁移要用的 60 个年月即可）
#   tar -czf uploadfiles-需要.tar.gz -C /www/wwwroot/gxhczx.gov.cn $(cat copy_dirs.txt)
# 拷回本地后解到仓库对应位置
tar -xzf uploadfiles.tar.gz -C backend/public/uploads/legacy/
# 拷完按本地文件认账：到位的改写成站内地址，缺的保留旧站外链
~/py-tools/bin/python tools/migrate/legacy_extract.py render \
  --in tools/migrate/out/articles.jsonl --manifest tools/migrate/out/media_manifest.csv \
  --out tools/migrate/out --local-check
php tools/migrate/legacy_import.php --in tools/migrate/out/articles.final.jsonl --commit \
  --archive-ids tools/migrate/out/deleted_ids.txt
php backend/bin/publish.php --out=backend/storage/publish
```

`--local-check` 按清单逐条看本地文件在不在，缺的继续保留旧站外链，补齐后再跑一次即可（幂等）；
清单文件本身不用手改（`media_manifest.csv` 若被删，重跑一次 `parse` 即再生）。

### 路径 B：现网抓取（已放弃，仅留记录）

2026-09-14 实测过 4 并发取样 40 条：5 分钟只落 39 张，且有地址卡在超时重试上，估算全量要数小时，遂删除抓取脚本 `tools/migrate/fetch_media.py` 与抓取记录。仅当服务器完全访问不了时才需要重新评估这条路；第三方图片（104 条）不在旧站目录里，只能现网取或用新站自己上传的图。

## 五、口径提示：图片到底在不在迁移范围内

现有几份方案与合同文本对“历史图片”的说法不一致，动手前需要先定口径（原句实读如下）：

无论按哪种口径，正文里的图片地址都已按“抓得到就改写站内地址、抓不到保留旧站外链”处理，不会出现死链；差别只在于要不要投入把 2,179 张（或全量 16,975 张）补齐。
