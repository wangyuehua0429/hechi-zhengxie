# 河池政协网 · 政协委员在线提交提案系统设计说明

> 编制日期：2026 年 9 月 14 日
> 配套文档：[用户分组与权限设计](用户分组与权限设计.md)、[稿库与内容状态设计](稿库与内容状态设计.md)、[api-contract.md](api-contract.md)
> 落地位置：`backend/routes/member.php`、`backend/src/Member/`、`backend/src/Proposal/`、`backend/templates/member/`、迁移 `005_member_proposal.sql`
> 给政协的简明版交付文件是另一份《政协委员在线提交提案系统建设方案》（.docx），只列功能清单；本文是给开发与运维看的实现说明。

## 1. 定位与本期范围

系统挂在主站内的独立门户 `/member/`，与内容管理后台 `/admin` 同一套路由与视图写法、同一个 PHP 入口，但**账号体系、会话、页面外壳完全分开**：

| 项 | 内容管理后台 | 提案门户 |
| --- | --- | --- |
| 入口 | `/admin` | `/member` |
| 账号表 | `sys_user` | `sys_member` |
| 会话名 | `PHPSESSID`（默认） | `zx_member` |
| 权限模型 | 角色 + 权限码 | 只需登录，只能看自己的提案 |
| 页面外壳 | `templates/admin/layout.php` | `templates/member/layout.php` |

本期只做**委员在线提交**与**提案委线上收件受理**。交办、答复、案号编排、征集批次与截止时间、提案公开、联名附议签名、承办单位账号、与“河池智慧政协信息管理平台”对接，均不在本期。

## 2. 数据模型

迁移 `database/migrations/{mysql,sqlite}/005_member_proposal.sql`（双方言同构），新增四张表：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sys_member` | `name`、`login_name`（唯一）、`password_hash`、`must_change_password`、`mobile`、`sector`（界别）、`committee`（专委会）、`org_title`（单位及职务）、`term`（届次）、`status`、`last_login_at`、`failed_attempts`、`locked_until`、`remark` | 委员账号。登录名取委员本人姓名，重名的由导入程序依次补序号（`张三`、`张三2`）；`mobile` 存手机号，既是联系方式也当备用登录标识 |
| `cms_proposal` | `member_id`、`proposer_type`、`proposer_name`、`sector`、`committee`、`contact_mobile`、`co_members`、`collective_name`、`category`、`title`（案由）、`problem_text`、`analysis_text`、`suggestion_text`、`status`、`returned_reason`、`reviewer_id`、`reviewed_at`、`review_note`、`submitted_at` | 提案主表。三段正文按纯文本存，段落用换行分隔 |
| `cms_proposal_attachment` | `name`、`stored_path`、`ext`、`size_bytes` | 附件。`stored_path` 是相对 `backend/storage/` 的路径，**不在 webroot 下**，只能经权限校验下载 |
| `cms_proposal_log` | `actor_type`（member／staff）、`actor_id`、`action`、`note`、`ip` | 提案流转记录。委员与提案委的动作都写这里 |

提案类别固定为“经济建设、政治建设、文化建设、社会建设、生态文明建设、其他”；提案人类别为“个人、联名、集体”。

## 3. 状态机与流转

状态定义集中在 `backend/src/Content/ProposalWorkflow.php`（与 `ArticleWorkflow` 同一写法），控制器、模板与仓储都从这里取，不散落状态字符串。

| 状态 | 中文 | 可做的动作 |
| --- | --- | --- |
| `submitted` | 已提交 | 提案委可受理、可退回补充；委员不能改 |
| `accepted` | 已受理 | 提案委可再退回补充（如需要补充材料） |
| `returned` | 已退回 | 委员可改稿重交，状态回到已提交 |

提案委动作与权限码：`accept`（受理，需 `proposal.review`）、`return`（退回补充，需 `proposal.review`，**必须填写退回意见**）。委员侧动作不设权限码，按“这份提案是不是本人的、状态是否可改”判断。

每一次提交、重交、受理、退回都写一条 `cms_proposal_log`；提案委的动作同时写 `sys_operation_log`，委员的登录与关键动作也写 `sys_operation_log`（`user_id` 记 0，主体在 `target_id` 与 `detail_json` 里）。

## 4. 委员端

| 路由 | 说明 |
| --- | --- |
| `GET /member`、`GET /member/login` | 门户首页：整幅红底图作页面底板，登录框浮在图上，下方接登录指南；已登录会被送到工作台 |
| `POST /member/login`、`POST /member/logout` | 登录与退出 |
| `GET/POST /member/password` | 首次登录强制改密；之后可随时改密 |
| `GET /member/proposals?status=&page=` | 我的提案列表，支持按状态筛选与分页（每页 10 条） |
| `GET /member/proposal/new`、`POST /member/proposal/create` | 填写并提交（提交即落“已提交”，本期不做草稿） |
| `GET /member/proposal/{id}` | 详情：正文、附件、状态、退回意见、受理意见、办理记录 |
| `GET /member/proposal/{id}/edit`、`POST /member/proposal/{id}/submit` | 仅“已退回”可进，改完重新提交 |
| `GET /member/proposal/{id}/word` | 下载本人提案的 Word 版 |
| `GET /member/proposal/{id}/attachment/{aid}` | 附件下载（校验归属） |

表单校验：案由必填且不超过 50 字；“情况与问题”“建议”必填，“分析”可选；三段各不超过 3000 字；联名提案必须填联名委员名单，集体提案必须填集体名称；联系电话必填。附件每次最多 5 个、单个不超过 32 MB，扩展名限 pdf／doc／docx／xls／xlsx／ppt／pptx／zip／rar／txt。

门户首页用甲方提供的图片 `政协提案系统.jpg`（自托管在 `backend/public/assets/member/header.jpg`）作**整页底板**：横屏按 `cover` 铺满视口，竖屏按 `contain` 完整铺在顶部、其余留给与底图下缘同色的底色 `#b30203`，因此窄屏也不会裁掉图上的标题；登录框浮在底图之上（宽度 420px 封顶），下方是“登录指南”面板。这一页自带完整 HTML 文档，经 `MemberView::bare()` 渲染，**不套 `member/layout.php` 外壳**——底板本身就是门面，再叠站头与页脚会把整幅底图切碎（与后台登录页同一处理）；页面结构里只保留一个视觉隐藏的 `h1` 供读屏使用。样式同样在 `backend/public/assets/member.css`（`.m-portal` 一节）。

## 5. 提案委后台

侧栏新增“提案管理”分组（提案收件／委员管理），按权限码显示。权限码写在 `backend/src/Content/Permissions.php` 的“提案”分组里，角色页自动出现勾选：

| 权限码 | 说明 |
| --- | --- |
| `proposal.view` | 提案收件列表与详情、附件下载 |
| `proposal.review` | 受理、退回补充 |
| `proposal.export` | 导出 Excel 收件清单与 Word 提案表 |
| `member.manage` | 委员名册导入、账号开通与停用、重置密码 |

迁移里同时建了内置角色“提案委”（`code=proposal_admin`，含上述四项），管理员角色按既有逻辑自动拥有全部权限。后台路由：`/admin/proposals`（列表与筛选）、`/admin/proposal/{id}`（详情）、`POST /admin/proposal/{id}/accept`、`POST /admin/proposal/{id}/return`、`/admin/proposals/export.xlsx`、`/admin/proposal/{id}/word`、`/admin/proposal/{id}/attachment/{aid}`、`/admin/members`、`/admin/members/import`、`/admin/members/credentials.csv`、`POST /admin/member/{id}/status`、`POST /admin/member/{id}/password`。

## 6. 名册导入与导出

**导入模板**（`GET /admin/members/import/template.csv`，UTF-8 带 BOM，Excel 双击即可编辑）表头固定：

```
姓名,手机号,界别,专委会,单位及职务,届次,备注
```

上传时自动识别 UTF-8／GBK 与 BOM；逐行校验，姓名必填、手机号建议填写（留空则该委员只能用姓名登录），手机号重复的行报错但继续处理其余行；登录名取姓名、重名自动补序号，不会出现登录名冲突。导入完成后给出“成功 N 行／失败 M 行 + 失败原因”报告。每人生成随机初始密码（10 位，去掉易混淆字符），**只在导入完成后下载一次**，库里只存 `password_hash`；一次性清单里的“登录名”列就是要发给本人的姓名（重名的带序号），早年按手机号开的账号该列仍是手机号。需要重发时走“重置密码”，新密码在委员管理页显示一次。

**导出**（`backend/src/Proposal/XlsxExporter.php` 与 `WordExporter.php`，用 `ZipArchive` 手写 OOXML，不引第三方库）：

| 导出 | 内容与排版 |
| --- | --- |
| Excel 收件清单 | 提案号、案由、提案人类别、提案人、界别、专委会、类别、提交时间、状态、办理时间、办理意见；带表头样式与自动筛选 |
| Word 提案表 | A4、案由三号居中、正文小四宋体、固定行距 28 磅、段落首行缩进 2 字；含提案人信息、三段正文、退回或受理意见、附件清单 |

委员端与提案委后台共用同一个 Word 生成器，两边口径一致。导出需要 PHP 的 `zip` 扩展，生产镜像已在 `deploy/php/Dockerfile` 里补上；环境缺扩展时导出入口返回明确错误，不静默降级。

## 7. 安全与隔离

1. **会话隔离**：委员门户用独立 `session_name`（`zx_member`），与后台会话是两个 Cookie，互不可见。
2. **首登强制改密**：`must_change_password=1` 时只能进 `/member/password`，其它业务页一律跳回。
3. **登录失败锁定**：连续输错 5 次锁定 15 分钟；登录标识不存在与密码错误给同一句提示，不泄露账号是否存在。登录标识按“登录名（本人姓名）→ 手机号 → 姓名”取候选，重名或手机号撞车时谁的密码对就登谁；账号的停用与锁定状态只在密码正确时才告诉本人，密码错一律回到同一句提示，避免把“这个标识有账号”“账号被锁了”变成免费的存在性断言。
4. **数据归属**：委员取提案一律按“提案号 + 本人 member_id”查，取不到按 404 处理，不区分“不存在”与“不是你的”。
5. **附件不入 webroot**：落在 `backend/storage/proposals/{提案号}/`，下载经 `FileResponse` 逐次鉴权，直链取不到。
6. **表单令牌**：所有 POST 校验 CSRF（沿用后台同一套 `Csrf`）。
7. **停用即时生效**：账号停用后，已登录的会话在下一次请求即失效。

## 8. 入口与部署接线

- 首页首屏“提案填报系统”条幅（`cms_home_banner.hero-1`）指向 `/member`：迁移 005 对存量库做一次更新，`backend/bin/seed.php` 的默认值同步改掉。
- “政协提案”栏目组（一级栏目号 501，含提案工作／提案查询／提案答复／提案督办）在栏目页标题右侧显示“进入提案填报系统”入口，实现见 `frontend/home/channel.html` 的 `#proposalEntry` 与 `frontend/home/js/channel.js`。
- 路由接线：`backend/public/index.php` 增加 `/member` 前缀挂载，`backend/public/router.php` 把 `/member*` 交给入口，`deploy/nginx/default.conf` 增加 `location /member`。
- 提案数据不写静态页、不进 sitemap、不做 301 映射，`/api/v1` 契约不变（对外接口不返回任何提案数据）。

## 9. 检查脚本与验收

新增 `tests/proposal-check.mjs`（63 项，临时 SQLite 库 + 真实服务）：名册导入（UTF-8 与 GBK、坏行、重复手机号、一次性密码清单）→ 委员登录与首登改密 → 提交（必填与长度校验）→ 后台收件、退回、受理 → 委员改稿重交 → 越权与附件隔离 → Excel 与 Word 导出可解析 → 停用后登录失败。

回归：`tests/` 其余脚本同步复跑，`tests/check-pages.mjs` 增加“栏目页·政协提案入口（501）”用例。
