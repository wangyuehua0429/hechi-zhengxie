## 1. 定位与本期范围

系统挂在主站内的独立门户 `/member/`，与内容管理后台 `/admin` 同一套路由与视图写法、同一个PHP入口，但**账号体系、会话、页面外壳完全分开**：

| 项 | 内容管理后台 | 提案门户 |
| --- | --- | --- |
| 入口 | `/admin` | `/member` |
| 账号表 | `sys_user` | `sys_member` |
| 会话名 | `PHPSESSID`（默认） | `zx_member` |
| 权限模型 | 角色 + 权限码 | 只需登录，只能看自己的提案 |
| 页面外壳 | `templates/admin/layout.php` | `templates/member/layout.php` |

本期做**委员在线提交**与**提案委线上收件受理**，并按2026-09-16需求确认单补齐：联名委员资料、办理联系人六项、建议承办单位、轻量富文本正文（整体 ≤2000字）、错别字勘误预留接口、提案委受理前调整提案（留痕）、批量导出与批量重置密码。交办、答复、案号编排、征集批次与截止时间、提案公开、联名附议签名、承办单位账号、与“河池智慧政协信息管理平台”对接，均不在本期。

## 2. 数据模型

迁移 `005`（提案系统建表）与 `006`（按最新需求调整），MySQL／SQLite双方言同构，差异只在方言与常量写法。

| 表 | 关键字段 | 说明 |

| `sys_proposal_unit` | `name`（唯一）、`sort_no`、`status`、`remark` | 市直单位清单，即“建议承办单位”下拉的可选项。由提案委在后台自行维护，初始为空，不预置任何未经确认的单位 |
| `cms_proposal_unit` | `proposal_id`、`unit_id`、`unit_name`、`sort_no` | 提案与承办单位的明细，一份提案最多5条。名称另存一份：单位从清单里删掉后，历史提案照样看得出当初报的是谁 |
| `cms_proposal_co_member` | `proposal_id`、`name`、`org_title`、`mobile`、`sort_no` | 联名委员资料 |

| `cms_proposal_attachment` | `name`、`stored_path`、`ext`、`size_bytes` | 附件。`stored_path` 是相对 `backend/storage/` 的路径，**不在webroot下**，只能经权限校验下载 |

提案类别固定为“经济建设、政治建设、文化建设、社会建设、生态文明建设、其他”；提案人类别为“个人、联名、集体”。

## 3. 状态机与流转

状态定义集中在 `backend/src/Content/ProposalWorkflow.php`（与 `ArticleWorkflow` 同一写法），控制器、模板与仓储都从这里取，不散落状态字符串。

| 状态 | 中文 | 可做的动作 |
| --- | --- | --- |
| `submitted` | 已提交 | 提案委可**调整内容**、受理、退回补充；委员不能改 |
| `accepted` | 已受理 | 提案委可再退回补充（如需要补充材料） |
| `returned` | 已退回 | 委员可改稿重交，状态回到已提交 |

提案委动作与权限码：`edit`（调整提案，需 `proposal.review`，只在 `submitted` 状态可用）、`accept`（受理，需 `proposal.review`）、`return`（退回补充，需 `proposal.review`，**必须填写退回意见**）。委员侧动作不设权限码，按“这份提案是不是本人的、状态是否可改”判断。

每一次提交、重交、调整、受理、退回都写一条 `cms_proposal_log`；提案委的动作同时写 `sys_operation_log`，委员的登录与关键动作也写 `sys_operation_log`（`user_id` 记0，主体在 `target_id` 与 `detail_json` 里）。

### 4.1表单口径

| 字段 | 规则 |
| --- | --- |
| 案由 | 必填，不超过50字 |
| 提案人类别 | 个人／联名／集体 |
| 联名委员 | 选“联名”时至少一位；每人填姓名（必填）、单位及职务、联系电话，可增删多行；姓名栏可搜委员名册带出单位职务与电话，名册外人员直接手填 |
| 正文 | **单一编辑框**（不再分三段），轻量富文本只开加粗、下划线、分段、有序／无序列表；字数按纯文本字符计（标点算、空格与换行不算），**整体不超过2000字**，超限即拦截并报出实际字数 |
| 建议承办单位 | 可搜索的多选下拉：输入关键词筛出后台维护的市直单位，点一下选中（选中项显示成标签，可单个取消），最多5个，选填；清单为空时页面提示联系提案委 |
| 办理联系人 | 姓名、单位、职务、联系地址、邮政编码、联系电话六项**全部必填**；首次填写后存入委员账号，下次自动带出；提交时快照写入该份提案 |
| 附件 | 每次最多5个、单个不超过32 MB，扩展名限pdf／doc／docx／xls／xlsx／ppt／pptx／zip／rar／txt |

### 4.2正文字数与清洗

字数口径写在 `backend/src/Content/ProposalBody.php`：HTML转纯文本 → 去掉所有空白 → 按字符数计。前端 `backend/public/assets/member-editor.js` 用同一算法（`Array.from(text.replace(/\s+/g, ""))` 的字符数），两边不一致会出现“页面上没超、提交却被挡”。入库前一律过 `HtmlSanitizer::cleanProposal()`（HTMLPurifier白名单只有 `p,br,strong,b,em,i,u,ul,ol,li`），颜色、字号、图片、链接、事件属性都被剥掉，导出与展示同一口径。

### 4.3编辑器与错别字勘误

正文编辑器复用后台自托管的SunEditor 3.3.3（MIT），只开加粗、下划线、有序／无序列表与清除格式几个按钮；脚本没加载或初始化失败时退回纯文本框，不阻断保存。字数实时显示在正文标题右侧，超限标红并在提交前拦下。

“建议承办单位”用同一套渐进增强的做法：`backend/public/assets/unit-picker.js` 把页面上原本的多选框换成可搜索的下拉（输入关键词过滤、点击选中、选中项做成可取消的标签、最多5个），**脚本没跑起来时页面上留下的就是原生多选 `<select multiple>`**，照旧能选能交。委员端填写页与后台“调整提案”页共用这一个组件。

“错别字勘误”按钮本期只接预留接口 `POST /member/proposal/check-text`：服务端回一句“功能待接入”并把已填内容原样带回表单，**不对接任何厂商**。编校服务（第二阶段智能编校模块，厂商四选一待定）确定后，在这一处换实现即可，前端按钮与表单不用改。

## 5. 提案委后台

侧栏“提案管理”分组（提案收件／委员管理／市直单位），按权限码显示。权限码写在 `backend/src/Content/Permissions.php` 的“提案”分组里，角色页自动出现勾选：

| 权限码 | 说明 |
| --- | --- |
| `proposal.view` | 提案收件列表与详情、附件下载 |
| `proposal.review` | 调整提案、受理、退回补充 |
| `proposal.export` | 导出Excel收件清单、单件与批量Word提案表 |
| `member.manage` | 委员名册导入、账号开通与停用、单个／批量重置密码 |
| `unit.manage` | 市直单位清单维护（006新增，授予内置“提案委”角色与管理员） |

后台路由：`/admin/proposals`（列表与筛选：状态／类别／界别／**承办单位**／关键词／日期）、`/admin/proposal/{id}`（详情 + 调整提案表单）、`POST /admin/proposal/{id}/edit`、`POST /admin/proposal/{id}/accept`、`POST /admin/proposal/{id}/return`、`/admin/proposals/export.xlsx`、`/admin/proposals/export.docx`、`/admin/proposal/{id}/word`、`/admin/proposal/{id}/attachment/{aid}`、`/admin/members`、`/admin/members/import`、`POST /admin/members/create`、`/admin/members/credentials.csv`、`/admin/members/batch-credentials.csv`、`POST /admin/members/reset-batch`、`POST /admin/member/{id}/status`、`POST /admin/member/{id}/password`、`/admin/units`、`POST /admin/units`、`POST /admin/units/import`、`/admin/units/import/template.csv`、`POST /admin/unit/{id}/rename|status|delete`。

**调整提案**（受理前）：可改案由、提案类别、正文、建议承办单位、联名委员与办理联系人六项。保存前自动比对，把改动字段写成一串中文清单（如“正文、建议承办单位”）；内容没变则不写留痕，只提示“没有改动”。每次真正改动都在 `cms_proposal_revision` 存一份改前快照，委员端详情页顶部出现“提案委已对内容作了调整”的提示与改动清单。

**市直单位清单**：单个添加、改名、停用／启用、CSV批量导入。被提案引用过的单位只能停用不能删除；改名会把已提交提案里的名称摘要一起改掉，否则列表筛选与导出口径会对不上。清单条目多时，委员端与后台改稿页都靠关键词搜索定位。清单为空时委员端该栏显示“市直单位名单还没配置，请联系提案委”，不预置任何未经提案委确认的单位名称。

## 6. 名册导入、单位清单导入与导出

**委员名册导入**（`GET /admin/members/import/template.csv`，UTF-8带BOM）表头固定：

```
姓名,界别,职务,联系电话
```

上传时自动识别UTF-8／GBK与BOM；逐行校验，**姓名与职务必填**——表里缺这两列（或它们的别名）会拒收整份文件，某一行留空则该行不入库并给出原因；界别与联系电话可以留空（留空联系电话的委员只能用姓名登录），联系电话重复的行报错但继续处理其余行；登录名取姓名、重名自动补序号，不会出现登录名冲突。老表头（`姓名,手机号,界别,专委会,单位及职务,届次,备注`）仍然照旧识别，早年导出的名册不用改。导入完成后给出“成功N行／失败M行 + 失败原因”报告。每人生成随机初始密码（10位，去掉易混淆字符），**只在导入完成后下载一次**，库里只存 `password_hash`；一次性清单里的“登录名”列就是要发给本人的姓名（重名的带序号），早年按手机号开的账号该列仍是手机号。

**手工新建账号**（`POST /admin/members/create`，委员管理页上的表单）：零星增补不用攒名册，一次可填1条或多条（默认三行，“添加一行”再增，最多50条），四列与导入模板一致：姓名（必填）／界别／职务（必填）／联系电话。整行空白的行忽略；建号走与导入同一个入口（`MemberImporter::importRows`），所以重名补序号、联系电话判重、姓名与职务必填的口径完全一致，不会出现两套规则。结果卡片给出“成功N条／失败M条”、没建成的条目与原因，并复用导入那套一次性密码清单（`/admin/members/credentials.csv`，下载即清）；没有脚本时表单照样能填三行并提交，增删行只是少点几下。

**批量重置密码**：委员管理页勾选若干账号（支持全选本页）执行“重置登录密码”，**每人生成不同的随机密码**，汇总成一份CSV清单，同样**下载一次即清**；重置后 `must_change_password=1`，委员下次登录必须先改密。

**市直单位清单导入**（`GET /admin/units/import/template.csv`）两列：`单位名称,排序号`（排序号可留空），UTF-8／GBK自动识别，重名行跳过并列出原因。

**导出**（`backend/src/Proposal/XlsxExporter.php` 与 `WordExporter.php`，用 `ZipArchive` 手写OOXML，不引第三方库）：

| 导出 | 内容与排版 |
| --- | --- |
| Excel收件清单 | 提案号、案由、提案人类别、提案人、联名委员、界别、专委会、办理联系人、联系电话、类别、建议承办单位、提交时间、状态、办理时间、办理意见；带表头样式与自动筛选 |
| Word提案表（单件） | A4、案由三号居中、正文小四宋体、固定行距28磅、段落首行缩进2字；含提案人信息、建议承办单位、联名委员、办理联系人、正文（保留加粗／下划线／列表）、退回或受理意见、附件清单 |
| Word提案汇总（批量） | 按当前筛选范围把全部提案装进同一个Word（上限200条），每件独立起页；本期只做系统内置格式，提案委的办理文件模板到位后再评估套版 |

委员端与提案委后台共用同一个Word生成器，三处口径一致。导出需要PHP的 `zip` 扩展，生产镜像已在 `deploy/php/Dockerfile` 里补上；环境缺扩展时导出入口返回明确错误，不静默降级。

## 7. 安全与隔离

1. **会话隔离**：委员门户用独立 `session_name`（`zx_member`），与后台会话是两个Cookie，互不可见。
2. **首登强制改密**：`must_change_password=1` 时只能进 `/member/password`，其它业务页一律跳回；改密完成后自助改密入口即关闭，忘记密码只能由提案委重置。
3. **登录失败锁定**：连续输错5次锁定15分钟；登录标识不存在与密码错误给同一句提示，不泄露账号是否存在。登录标识按“登录名（本人姓名）→ 手机号 → 姓名”取候选，重名或手机号撞车时谁的密码对就登谁；账号的停用与锁定状态只在密码正确时才告诉本人，密码错一律回到同一句提示，避免把“这个标识有账号”“账号被锁了”变成免费的存在性断言。
4. **数据归属**：委员取提案一律按“提案号 + 本人member_id”查，取不到按404处理，不区分“不存在”与“不是你的”。
5. **名册检索最小化**：`/member/roster` 只回姓名、单位及职务、联系电话三个字段，不回登录名、界别分布与账号状态，且关键词为空不返回任何数据。
6. **附件不入webroot**：落在 `backend/storage/proposals/{提案号}/`，下载经 `FileResponse` 逐次鉴权，直链取不到。
7. **表单令牌**：所有POST校验CSRF（沿用后台同一套 `Csrf`）。
8. **正文本轮清底**：入库前过提案白名单清洗，正文里的脚本、事件属性与越界样式进不了库，也就进不了页面与导出的Word。
9. **停用即时生效**：账号停用后，已登录的会话在下一次请求即失效。

- “政协提案”栏目组（一级栏目号501，含提案工作／提案查询／提案答复／提案督办）在栏目页标题右侧显示“进入提案填报系统”入口，实现见 `frontend/home/channel.html` 的 `#proposalEntry` 与 `frontend/home/js/channel.js`。
- 路由接线：`backend/public/index.php` 增加 `/member` 前缀挂载，`backend/public/router.php` 把 `/member*` 交给入口，`deploy/nginx/default.conf` 增加 `location /member`。
- 静态资源：`/assets/member.css`、`/assets/member-editor.js` 与自托管的 `/assets/editor/*`（SunEditor）。
- 提案数据不写静态页、不进sitemap、不做301映射，`/api/v1` 对外接口不返回任何提案数据；唯一例外是门户内的 `/member/roster`，只对已登录委员开放且只回三个字段。

## 9. 检查脚本与验收

`tests/proposal-check.mjs`（115项，临时SQLite库 + 真实服务）：名册导入（UTF-8与GBK、坏行、重复手机号、一次性密码清单）→ 市直单位清单（导入、重名、停用）→ 委员登录与首登改密、改密后关闭自助入口 → 提交（必填、案由长度、正文2000／2001字边界、邮编、联名委员、承办单位最多5个与无效单位、富文本清洗、可搜索下拉与无脚本回退都在页面上）→ 名册检索与勘误预留接口 → 后台收件、退回、改稿重交 → 提案委调整提案（留痕、委员端提示、无改动不写留痕）→ 受理 → 越权与附件隔离 → Excel／单件Word／批量Word导出可解析 → 批量重置密码与一次性清单 → 停用后登录失败。

回归：`tests/` 其余脚本同步复跑；迁移006在SQLite上实跑，MySQL侧只做语句与方言复核（本机无MySQL实例）。
