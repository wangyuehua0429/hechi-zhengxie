## 2. 红色语义

红色只表达三种意思：**品牌标识**（顶栏标识块、主按钮）、**危险操作**（删除、撤回、红叉）、**需要处理**。概览页因此把“需要处理”做实——**待审／退回**单独一行、有值时数字用 `--brand-ink`，为0时用 `--muted` 降字重并写“暂无待处理”；稿件总数与其余稿库计数一律 `--ink`／`--muted`，收进“按稿库看全部状态”的一行摘要与折叠区。八张卡全标红时红色就不再表示重点，所以红色只给待办，不给“总数”。

深色下的红要分两个角色：**当底**的 `--brand` 取更暗的一档（`#b0343a`，白字6.1:1），**当字**的 `--brand-ink` 反过来提亮（`#f0949a`，深底7.5:1）。浅色下两者同值，所以组件里凡是用红色写字的地方都写 `--brand-ink`，用红色当底的地方才写 `--brand`。

成功与危险同理：**当底的**用 `--ok-fill`／`--err-fill`（深色下也不改值，白字分别5.37:1／5.44:1），**当字的**才用 `--ok`／`--err`（深色下提亮）。第一版把 `--ok`／`--err` 直接拿去当底压白字，深色下只有2.57:1／4.04:1，已改。

## 3. 栏目导航条（两级）

栏目共 43 个，其中 25 个一级项、5 个含子栏目。规则：

- 默认只渲染“全部栏目 + 25 个一级项”（约 2 行），不铺开 43 个 chip。
- 选中项落在某个多子栏目组里时，该组展开显示子 chip；形态仍是导航条，不做下拉。
- **母栏目是开关**：点一次 = 按整组筛选并展开子栏目（母栏目实心红、子栏目浅红底）；已经是整组筛选状态时再点一次 = 收起子栏目、回到“全部栏目”。展开中但未被选中的母栏目用浅红底，与自己的子栏目连成一组。
- **一级项与子栏目分开传参**：一级项走 `?group=<一级栏目号>`，子项走 `?channel=<栏目号>`。原因是“栏目号 401 既是‘政协会议’这一组的组号，又是组内‘全体会议’的号”，只看栏目号无法区分用户想筛整组还是某一个。
- 一级项上的数字是该组各子栏目之和；数字口径与当前列表筛选（稿库 + 关键词）一致。

## 5. 四个必须遵守的坑

1. **提交中的按钮不能 `disabled`。** 新建稿件的“保存并发布／保存为草稿”与稿库流转按钮都靠 `name/value` 传参，按钮被禁用后参数不会提交，服务端就收不到 `status`／`action`。统一改用 `aria-busy` + `.is-busy` + `pointer-events:none`。
2. **图标一律内联 SVG。** 项目无 `composer.json`、无 npm 依赖，内网部署也不能依赖外部图标 CDN；统一放在 `backend/templates/admin/_icons.php`，用 `require` 取数组（不是定义函数，避免同请求内重复声明）。
3. **深色令牌写了两份，必须同步。** 一份在 `@media (prefers-color-scheme: dark)` 的 `:root:not([data-theme="light"])` 里，一份在 `:root[data-theme="dark"]` 里（前者管跟随系统，后者管用户手动覆盖）；改一处就要改另一处。另外主题引导必须走外链脚本 `assets/theme.js`——后台CSP的 `script-src` 只放行登录页那一个内联脚本哈希，再加内联脚本会让登录页之外的主题引导被浏览器直接拦掉。
4. **`position: sticky` 要挂在包含块够高的那一层。** 批量条一开始把 `is-sticky` 加在 `.bulk-bar` 上，而它的包含块就是那根条子本身（可偏移量恒为0），等于没吸；现在类名挂在 `<form class="bulk-form">` 上——它的包含块是整页的 `.main`，才真的吸得住。同理，`.form-actions` 能吸底是因为父级是整张长表单。

## 6. 深色模式

- **怎么选主题**：默认跟随系统（纯CSS，首帧就正确）；顶栏那枚开关把选择写进 `localStorage.hechi-admin-theme`，`assets/theme.js`在 `<head>` 里同步读出来写 `<html data-theme>`，所以刷新、跳页都不会闪一下浅色。
- **组件不用改**：所有颜色都走令牌，深色只重定义 `:root` 的那一组值（含投影、品牌光晕、表单描边）。新增组件时如果又写了裸十六进制颜色，深色一定穿帮。
- **对比度实测（深色，按WCAG相对亮度公式在渲染页上量）**：正文14.89、次要文字6.54、品牌红链接7.49、“已发布”标签8.36、实心红chip上的白字6.18、禁用按钮5.58、表头9.32——全部≥4.5:1。
- **原生控件也要跟着变**：`:root` 只写 `color-scheme: light`，系统深色由媒体查询、用户手选深色由 `data-theme="dark"` 改成 `dark`；写 `light dark` 会让“系统深色＋用户选浅色”时下拉弹层、滚动条仍是深色（实测已修正：显式浅色时 `color-scheme` 为 `light`）。
- **图片类内容不调色**：深色下站内横幅、头条缩略图仍是原图，不做降亮处理（内容真实优先）。
- **第三方编辑器也要接管**：`assets/editor/admin-editor.css` 里用 `.writing-paper .sun-editor(.sun-editor-editable)`重定义了SunEditor自带的那批变量（`--se-main-color`、`--se-edit-background-color` 等）。不接管的话，输入框底色跟着令牌变深，编辑器却把文字写死成浅色下的深灰——2026-09-17实测原题三列与来源四个输入框只有1.06:1、正文纸面还是纯白。该文件委员门户也用，所以每个 `var()` 都带原值兜底（那边是 `--m-*` 令牌）。
- **占位文字**：`admin.css` 里 `input::placeholder／textarea::placeholder` 统一切到 `--muted`，浏览器默认的 #757575深底上只有3.63:1。

## 7. 本轮未做

- 首页管理四页未按本规范逐页调整（那边有并行改动，避免冲突）。2026-09-12 的站内横幅出图建议与选图预览只按上表补了组件约定，未做整页视觉重排。
- 主题只有“跟随系统 + 一键切换”，没有第二级选项（固定浅色／固定深色／定时切换）；也没做打印样式（后台偶尔要打列表，打印仍按浏览器默认）。
- 深色下没有单独校对图片类内容的观感（横幅、头条缩略图按原图出）。
- 后台是同步渲染，暂不做骨架屏／加载占位；若以后改成异步列表，这条要补。
- 批量提交被服务端拒绝（权限、CSRF、状态不合法）时，篮子已经在提交那一刻清空了，用户得重新勾一遍；要改成“服务端确认成功后再清”，需要在回跳地址上带一个信号。
- 主题与侧栏展开态存在 `localStorage` 里，但没监听 `storage` 事件——同一浏览器开两个标签页时，另一个要刷新才跟上。
- 界面的脚本级行为（跨页篮子、主题开关、Shift区间选择、吸顶）目前只有标记级断言兜底，没有浏览器自动化用例；要不要为后台引入浏览器测试，留着决定（本机是 `playwright-cli`，不是零成本）。
