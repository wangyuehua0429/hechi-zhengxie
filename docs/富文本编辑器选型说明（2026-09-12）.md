# 河池政协网 · 稿件正文富文本编辑器选型说明

> 编制日期：2026 年 9 月 12 日
> 结论：**选 SunEditor 3.3.3（MIT）**，本地自托管预构建包、不引构建链；服务端另配一份 HTMLPurifier 白名单，作为唯一安全边界。
> 检索与实测方式：GitHub REST API、npm registry、各项目官网，以及本机实测（PHP 8.5.10、Node 26、Chromium）；检索与实测日期 2026 年 9 月 12 日。
> 决策记录：2026 年 9 月 12 日确定选型为 SunEditor 3.3.3。
> **落地状态（2026-09-12）**：编辑器与清洗层当日已接入并上线，实施记录见第 4.4 节；现网口径（图片 ≤ 2 MB、正文可用字体／字号／文字颜色／背景色）见 4.4 表末两行。

## 1. 背景与约束

后台稿件编辑页的正文**改造前**是一个 18 行的 HTML 文本框（`backend/templates/admin/article_edit.php` 的原 textarea，现已作为编辑器的降级通道保留），编辑要么手写 HTML，要么从 Word／网页粘贴后自行清理。

比录入体验更紧要的是安全：正文全链路没有清洗。`ArticleController::normalizeContent()`（`backend/src/Admin/ArticleController.php:981`）只在纯文本分支做 `htmlspecialchars`，一旦正文里出现任意 `<tag>` 就原样入库；入库之后 `backend/src/Api/ArticleController.php` 的 `show`、`backend/src/Publish/Publisher.php:191`、`frontend/home/js/detail.js:90` 三处都是原样输出。这是引入编辑器之前就已存在的洞，上编辑器会放大它，因此编辑器与清洗层必须同一批落地。

本次选型受四条约束：

| 约束 | 事实 |
| --- | --- |
| 许可宽松 | 政府项目、要求源码可控，排除 GPL 与商业授权 |
| 免构建自托管 | 工程无 composer.json、无 npm 构建链（`backend/src/bootstrap.php:5`），编辑器必须是可直接落盘的预构建产物，且不依赖 CDN |
| 能力范围 | 基础排版（粗体／斜体／下划线／标题／有序无序列表／缩进／对齐／链接／清除格式）+ 正文插图 + Word／网页粘贴保留格式并清洗 |
| 存量兼容 | 库内 407 篇稿件中 71 篇有正文，实际用到的标签只有 `div`（1958 处）、`p`、`br`、`strong`、`img`（53 处）、`a`、`video`（1 篇），正文中无 `script`／`on*`／`javascript:` 等可疑内容 |

### 2.2 剪贴板保真对照（试验台实测）

试验方式：四个候选各占一个 iframe，用真实剪贴板与键盘粘贴注入同一份样本，输出统一过同一份 HTMLPurifier 白名单后比对。试验台位于仓库外 `~/Downloads/editor-bakeoff/`，报告见同目录 `report.html`。

| 编辑器 | Word 样本原始／清洗后字符 | 清洗后正文字数 | 保留格式 | 内容级问题 |
| --- | --- | --- | --- | --- |
| SunEditor 2.47.12 | 823／289 | 110 | 加粗、斜体、下划线、删除线、居中 | 输出带前导空段；版本带未修复高危公告 |
| SunEditor 3.3.3 | 817／271 | 104 | 加粗、斜体、下划线、居中，并把 Word 编号段落识别为真列表 | Word 结构下的 `<del>` 内容按“修订痕迹”丢弃 |

| wangEditor-next 6.4.1 | 1416／257 | 104 | 加粗、斜体、下划线、居中 | 无条件丢弃 `<del>` 内文字；所见非所得落差最大 |

### 2.3 四个候选共有的四条风险

这四条与最终选谁无关，都必须在实现时处理：

1. **Word 图文混排的图片必丢。** Word 剪贴板给的是 `file:///C:/...` 本地路径，浏览器拒绝加载，服务端白名单也只放行 http／https／mailto 与相对路径。
2. **base64 图片静默消失。** 编辑器 DOM 里留得住，保存时被白名单按协议剥掉。
3. **相对路径被改写成绝对地址。** 实测 `images/channel/art61454-1.jpg` 被解析成 `http://<后台域名>/images/channel/...`，且白名单放行 http，旧稿重存会把图片地址写死。库内 29 篇正文带 `<img>`，此条必须处理。
4. **表格会被拆成单元格文字**（本次需求不含表格，需在界面上说明）。

## 3. 采用结论

### 3.1 选 SunEditor 3.3.3

1. **许可最简。** MIT，可自托管、可商用、可闭源分发，只需保留版权与许可文本；无付费版，无品牌标识，不存在“要不要花钱去标记”的决策。
2. **对当前版本无已知漏洞。** 3.3.3 在修复版 3.1.4 之后；同线的 v2.47.12 反而带着一条无修复的高危公告。
3. **满足免构建约束。** 预构建产物 4 个文件，中文语言包随包提供，可直接落盘。
4. **能力对口。** 粘贴清洗有现成配置（`strictMode`／`attributeWhitelist`／`allowedClassName`），图片上传走插件选项，粘贴白名单与后端 HTMLPurifier 白名单同构，便于两边对齐查错。

### 3.2 不用 v2.47.12 与其余候选

- **SunEditor 2.47.12**：虽保住 `<del>` 文字且 API 更简单（顶层 `imageUploadUrl`／`pasteTagsWhitelist`），但 npm audit 报一条 high 且 v2 线无修复，官网已把它列为 “v2 Legacy”，不作为新项目基线。
- **Jodit 4.15.1**：Word 保真最好且无已知漏洞，可作为备选；因状态栏标识的存在与隐藏方式需要商务口径确认，本次不采用。
- **wangEditor-next 6.4.1**：无条件丢弃 `<del>` 内文字，且编辑器所见与入库结果落差最大。
- **Quill 2.0.3**：无内置图片上传、Word 粘贴与清洗均需自研，等于把想省掉的工作量加回来。

### 3.3 随之确定的实现约束

1. **服务端白名单修正三条**：白名单补 `div`（存量 1958 处）；去掉 `figure`／`figcaption`（HTMLPurifier 只支持 HTML 4.01／XHTML 定义，写了会报警告且照样丢弃）；`video` 用自定义元素补（1 篇存量稿件 61454 带视频，实测可保留 `src`／`poster`／`controls` 同时仍剥掉 `onerror` 与 `javascript:`）。
2. **CSP 分范围**：只在 `/admin` 与 `/article/` 生效；`frontend/home/index.html` 第 9 行与 `backend/templates/admin/login.php:88` 有内联脚本，需用 sha256 哈希放行或外移成文件，不能直接全站套 `script-src 'self'`。
3. **两个适配层**：粘贴图片自动上传（或明确提示不支持）；保存前把本站绝对地址还原为相对路径。
4. **缓存目录**：HTMLPurifier 的定义缓存默认写在 vendor 内，须显式指向 `backend/storage/` 下并预先建目录，否则只读部署会每请求重建并告警。

### 4.2 接入点

- 编辑页：`backend/templates/admin/article_edit.php:151-153` 的 `textarea` 保留且默认可见，旁加挂载点，初始化成功后再隐藏，保持既有渐进增强风格；提交字段名仍为 `content_html`。
- 脚本：`backend/public/assets/admin.js` 抽出取值函数（有编辑器取编辑器内容，否则取 `textarea.value`），预览、字数与提交前同步都走它。
- 资源加载：`backend/templates/admin/layout.php:97-98` 目前全局引入，需新增仅本页加载的插槽。
- 图片上传：新增 JSON 接口，按 SunEditor 3 的契约返回 `{"result":[{"url","name","size"}]}`，CSRF 通过插件 `uploadHeaders` 传递；不复用现有的 302 表单接口（它把图追加到正文末尾，无法在光标处插入）。
- 取值 API 注意：v3 与 v2 不同，内容读写走 `editor.$.html.get()`／`set()`，不是 `getContents()`／`setContents()`。
