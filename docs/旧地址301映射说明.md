# 旧地址 301 映射说明

> 编制日期：2026 年 9 月 12 日
> 依据：旧站程序与目录（`zhengxie2026/gxhczx.gov.cn/`，本次实际读取）、新库表结构（`database/migrations/*/001_init.sql`）、接口契约第 7 节。
> 生成工具：`php backend/bin/redirects.php`；判定与口径写在 `backend/src/Publish/RedirectMap.php`，改口径要同时改这两处。

## 一、为什么要做

旧站有大量对外地址已经散播出去：搜索引擎收录的静态文章页、其他网站的外链、微信里发过的链接。新站上线后旧地址不能变成 404，否则 SEO 与外链双失。合同与方案都把“旧 URL 统一 301 映射”列为必做项（见 [下阶段开发计划（2026-09-11）.md](下阶段开发计划（2026-09-11）.md) 阶段 D 第 5 项）。

## 二、旧地址形态（实读旧站程序与目录得出）

| 旧地址形态 | 出处（本次实读） | 语义 |
| --- | --- | --- |
| `/news_view.php?id=<稿件号>` | `gxhczx.gov.cn/news_view.php` 第 8—19 行 | 按稿件号取一篇详情 |
| `/cq_view.php?id=<稿件号>` | `gxhczx.gov.cn/cq_view.php` 第 8—19 行 | 同上（另一套模板） |
| `/html/news-view-<稿件号>.html` | `gxhczx.gov.cn/html/` 下 53,542 个静态文件 | 旧站静态文章页 |
| `/news_list.php?id=<栏目号>` | `gxhczx.gov.cn/news_list.php` 第 8—14 行 | 按栏目号取列表 |
| `/cq_list.php?id=<栏目号>` | `gxhczx.gov.cn/cq_list.php` 第 8—13 行 | 同上（另一套模板） |
| `/news_list_about.php?id=<栏目号>` | 文件存在；首页数据里出现 `?id=202` | 一页式栏目（政协领导等） |
| `/qy_list.php` | 文件存在；首页数据里出现该地址 | 县（区）政协聚合页 |
| `/zl<日期>/` | `gxhczx.gov.cn/` 下 13 个目录：`zl20180106`、`zl20190105`、`zl20190923`、`zl20200105`、`zl20210225`、`zl20210331`、`zl20211008`、`zl20220108`、`zl20220331`、`zl20230206`、`zl20240131`、`zl20250206`、`zl20260225` | 旧站专题（两会）目录 |
| `/home.php`、`/news-list.html` | 文件存在 | 旧站入口页 |
| `/uploadfiles/<年月>/<文件>` | 首页数据里出现（`20211207/20211207172652_396.docx` 等） | 旧站附件与图片 |

两个必须写清楚的事实：

1. **旧站根目录下没有 `news-view-*.html`**（`html/news-view-*.html` 才是静态页的实际位置），旧站 vhost 也没有相关 rewrite（`server/panel/vhost/rewrite/gxhczx.gov.cn.conf` 为空）。此前 `deploy/nginx/default.conf` 里手写的那条按前缀跳转的规则因此已删除，它既匹配不到真实地址，`^~` 前缀匹配里也取不到 `$1`，会把命中的路径统一跳到 `/article/`。
2. **`id` 沿用旧库号**（接口契约第 1 节），所以旧地址里的稿件号与栏目号可以直接拼出新地址的前半段，不需要额外的对照表。

## 三、新地址口径

| 旧地址 | 新地址 | 说明 |
| --- | --- | --- |
| 详情（静态页 + 两个脚本） | `/article/<稿件号>.html` | 发布器产出的详情静态页，Nginx 直出 |
| 栏目列表（三个脚本） | `/channel/<目录名>/` | 目录名规则见 `backend/src/Publish/StaticPaths.php` |
| `/qy_list.php` | 县（区）政协栏目的静态页 | 栏目号 `qy` |
| `/zl<日期>/` 与 `/zl<日期>` | 专题栏目的静态页 | 具体专题与旧目录的一一对应待甲方确认 |
| `/home.php`、`/news-list.html` | `/` | 旧站入口页 |

**栏目目录名为什么不是纯 slug**：前端 `channel.json` 的 slug 是**一级栏目**的标识，902—906（政协动态的五个子栏目）都写 `zhengxie-dongtai`，601—607（党派团体七个子栏目）都写 `dangpai-tuanti`。直接拿它当目录名，43 个栏目只会写出 25 个静态页（后写的覆盖先写的），sitemap 里还会出现重复地址。现在的规则是：slug 唯一时用 `/channel/<slug>/`，slug 重复的这一组都补上栏目号，写成 `/channel/<slug>-<栏目号>/`——例如 `/channel/zhengxie-dongtai-902/`、`/channel/zhengxie-dongtai-904/`。这条修正已纳入 `tests/redirect-check.mjs`。

## 四、怎么生成

```bash
# 1. 按库内内容生成/更新映射（写 sys_url_redirect，不动其它表）
php backend/bin/redirects.php

# 2. 上线前：同时产出 Nginx 片段、核对用 CSV 与报告，并校验每条映射的目标产物真的存在
php backend/bin/redirects.php \
  --out=backend/storage/publish \
  --check=backend/storage/publish \
  --legacy-site="/path/to/zhengxie2026/gxhczx.gov.cn"
```

产物（写在 `--out` 目录的 `redirects/` 下）：

| 文件 | 内容 |
| --- | --- |
| `nginx-301.conf` | Nginx 片段：把旧地址形态转给 PHP 入口判定；`server{}` 里 `include` 它 |
| `url-map.csv` | 旧地址 → 新地址逐条清单，交甲方核对 |
| `report.txt` | 分类小计、目标缺失明细、未登记的旧地址清单 |

参数：`--dry-run` 只统计不写库；`--legacy-site=<旧站目录>` 拿真实旧站目录对照，列出未登记的旧地址；`--check=<发布目录>` 校验目标文件是否存在，缺失时退出码为 1；`--fastcgi=` / `--script=` 覆盖 Nginx 片段里的后端地址。

**每次生成都是全量重算**：除按 `old_path` 增改映射外，还会清掉这一轮不再登记的旧地址（`清掉的失效映射` 一行给出条数）。稿件转 `archive`、栏目下线之后旧地址必须一起失效——否则旧地址会 301 到一个已经被发布器清掉的页面。`--check` 校验的是**真正落库的那份表**（不是内存里刚算出的清单），所以库里若残留上一轮的旧记录，这一项会直接报出来。

## 五、运行期怎么判定

映射明细在 `sys_url_redirect` 表里（`old_path` 唯一索引）。请求进来后：

1. Nginx 按生成片段把旧地址形态转给 PHP 入口（`backend/public/index.php`）；
2. 入口用 `HechiZx\Http\LegacyRedirect` 归一化路径与 `id`／`q` 参数后查表，命中就 301 并把 `hits` 加一，未命中照旧 404；
3. 本地开发用 `backend/public/router.php`，同样在“文件不存在”时才查表，正常静态请求不连库。

两点口径：

- **只登记能打开的新地址**。详情映射只收“已发布 + 有正文”且在当前公开口径下会产出静态页的稿件——与发布器的产出条件完全一致，所以不会出现 301 指到 404。未审、无正文的老稿件不登记，这些旧地址返回 404、不产静态页也不做跳转。公开口径由 `backend/config/config.php` 的 `content.enforce_public_scope` 决定：`true`（近 3 年，超出年限的 `archive` 稿不登记）、`false`（当前默认，放开年限、归档稿照常登记）；迁移期的年限切分见 [旧库迁移说明](旧库迁移说明.md)。
- **县区子站不管**。旧地址带 `q=<县区号>`（主站是 22）的属县区子站，本期不做迁移，也不产生映射，请求照旧 404；`site_id` 维度已预留。

2. 旧站静态文章页 53,542 个、专题目录 13 个、根目录无 `news-view-*.html`：`ls`／`find` 实测。
3. 旧站 vhost 与 rewrite 配置：`server/panel/vhost/rewrite/gxhczx.gov.cn.conf`（空）、`date/file_history/www/server/panel/vhost/nginx/www.gxhczx.gov.cn.conf`（无旧地址规则）。
4. 新库 `sys_url_redirect` 表结构：`database/migrations/sqlite/001_init.sql`、`database/migrations/mysql/001_init.sql`。
5. 栏目 slug 重复情况：43 个栏目中 23 个共用 5 个 slug（`zhengxie-dongtai` 5 个、`zhengxie-huiyi` 4 个、`zhengxie-tian` 4 个、`dangpai-tuanti` 7 个、`zhengxie-yiyuan` 3 个），解析 `frontend/home/data/channel.json` 得出；修正前发布器只写出 25 个栏目静态页（本次实跑验证）。
6. 样例库生成 369 条映射、`--check` 全部命中、运行期 301 与 hits 计数正常：`node tests/redirect-check.mjs`（50 项全通过）。
7. D-2 重跑（2026-09-14，换成 2026-09-05 全量备份）实跑：映射 8,478 条（详情页 2,773 × 3 条 + 栏目 129 + 入口 3 + 县区聚合 1 + 专题目录 26），清掉上一轮失效映射 1,224 条（408 篇转 `archive` 稿件 × 3 条），`--check` 全部命中；带 `--legacy-site` 对照旧站目录时，53,542 个旧静态页中已登记 1,140 个（其余是新库没有“已发布+有正文+public”的稿件）。

**推断**

1. 旧站静态文章页对外的实际曝光路径以 `/html/news-view-<id>.html` 为主：依据是首页数据与旧站目录里出现的地址写法一致，且根目录无同类文件。

**未知（未核实）**

1. 全量迁移后未登记旧地址的实际数量：现仅按 70 篇样例稿件验证，未迁移的老稿件尚未进库。
2. 旧站附件与图片在迁移后的存放路径：事项三已记录为“纳入迁移”，具体路径方案未定。
3. `/fupin` 与 13 个专题目录在新站中各对应哪个栏目：未与甲方确认。
