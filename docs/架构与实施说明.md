# 河池政协网 · 开发与架构说明

> 依据《河池政协网开发思路与技术栈方案》（2026-09-01）整理，随实现演进更新。当前以 `frontend/home/` 前端静态版为实际交付，本文构建为规划中的目标架构。

## 1. 系统分层

```
┌─ 前端层：主站响应式门户（PC/手机/微信），全文静态化页面 ＋ 预留子站皮肤接口（本期：frontend/home）
├─ API 层：内容/资源 REST API（前台、后台、校对、未来多端共用的数据出口）
├─ 应用层：PHP CMS（栏目/文章/附件管理、发布调度、静态化生成、URL 重写；多站点 site_id 预留）
├─ 服务层：智能编校微服务（本期，独立 Python 部署）· 图片管理平台（独立项目，可后置）
├─ 数据层：MySQL（开发+生产统一，本期不切国产库）＋ Redis 缓存 ＋ 对象存储 ＋ 静态文件存储（Nginx 直出）
└─ 基础层：移动云 IaaS ＋ 安全组/WAF/备份/监控
```

## 2. 数据模型（新库，规划）

核心原则：**内容/资源统一入库、先入库后使用**，以 API 为数据出口；栏目、文章、附件、专题统一元数据模型（site_id / channel_id / 元数据 / 发布时间 / 公开范围）。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| sys_site | site_id、站点标识、域名、模板主题、状态 | 多站点预留，本期只启用主站 |
| sys_channel | channel_id、site_id、父级、栏目名、栏目类型、URL 别名、排序、权重 | 支持 17 个一级栏目与二级子栏目 |
| cms_article | article_id、site_id、channel_id、标题、副题、正文、摘要、作者、来源、发布时间、置顶/头条、URL 别名、发布状态、公开范围 | 发布状态仅草稿/已发布/下线 |
| cms_attachment | article_id、存储 key、类型、大小、下载计数 | 历史图片附件迁移后挂接 |
| sys_url_redirect | 旧路径 → 新路径 | 301 映射，保 SEO 与外链 |
| sys_user / sys_role | 权限到“站点 × 栏目” | 稿件审核终审由政协办公室在系统外把关 |
| cms_article_sync | 上/下行稿件互通 | 预留，依赖县区子站开通 |
| sys_operation_log | 操作/登录日志 | 留存 180 天 |
| 编校扩展 | 文章编校状态/编校单编号；独立编校词库表（领导、行政区划、忌讳词、本地提法） | 本期使用 |

## 4. 关键技术点

1. **数据库方言迁移**：本期生产统一 MySQL；SQL 层按方言适配隔离，为日后切换达梦/金仓预留平滑通道。
2. **URL 301 映射**：迁移脚本按旧库文章 ID 批量生成映射表，Nginx/PHP 层统一 301。
3. **全文静态化与增量发布**：发布即生成静态 HTML，内容变更触发对应页增量刷新；静态文件由 Nginx 直出。
4. **内容/资源 API 契约**：前台/后台/校对/多端统一走 REST，先定义契约与版本再实现前端。
5. **多站点预留**：nginx virtualhost + 单 CMS 多站点（site_id 维度），本期只建主站。
6. **编校模块边界**：以独立 Python 服务接入，接口契约与字段先行，不与 CMS 核心耦合。
7. **无障碍与安全合规**：接入政务无障碍组件；落实等保二级（前后台分机部署、日志 ≥6 个月、敏感词过滤、防篡改/防攻击/防病毒）；补齐 HTTPS 与站点地图/网站标识。
8. **数据安全**：涉密稿件不发外网、不调用厂商接口；本地词库存政协自有服务器；迁移全程保密协议 + 多重备份。

## 5. 实施节奏

一期（主站 + 校对模块）9/1 启动：主站对照 61 天窗口（9/1—11/1），11/1 关停旧政务云；校对模块以独立 Python 服务同步推进，采用“接口契约先行、并行开发、联调联测”。若工期紧张，以主站先上线为优先，校对作为一期紧后段收尾。子站与稿件互通本期不做，按预留接口后续开通。
