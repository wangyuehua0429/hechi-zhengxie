# 河池政协网 · 新版首页（前端静态版）

本期只做前端、不写后端；数据以 `data/home.json` 静态快照复用现网“广西河池政协网”内容，后端就绪后以 REST API 平替该数据源。

## 预览

浏览器直接打开 `index.html` 时，`fetch` 本地 JSON 会被拦截，需通过本地静态服务器访问：

```bash
cd frontend/home
python3 -m http.server 8899
# 打开 http://127.0.0.1:8899/index.html
```

## 数据源（接口优先，静态兜底）

页面不直接写 `fetch("data/xxx.json")`，统一走 `js/data-source.js`：

- 先探一次 `/api/v1/health`，能通就走**内容接口**（生产、本地 PHP 服务）；
- 探不通（GitHub Pages 这类纯静态托管）就自动回退到 `data/*.json` 快照，预览照常可用；
- 地址栏开关：`?api=1` 强制接口、`?api=0` 强制静态快照（存 sessionStorage，翻页保持）；
- 接口返回 404 表示“这篇确实没有/未发布”，此时**不回退快照**，以免把已下线内容重新显示出来。

调试时可用 `window.SITE_DATA.mode()` 看当前生效的数据源。

## 站头动态收缩（2026-09-11）

站头横幅只有首页全幅显示（`--mast-ratio`，1920:550）。点主导航里的栏目进入内页后，站头收窄为 `--mast-ratio-folded`（1920:183，约全幅三分之一；640px 以下窄屏为 1920:260），导航条以下的主体整体上提，露出更多内容；收缩态不再显示“政治协商 民主监督 参政议政”标语，横幅本身与站名标志保留——横幅居中裁切，标志等比缩小并沿用全幅时的左上角位置（不居中）。

收窄与展开的高度都按 `--mast-ratio`、`--mast-ratio-folded` 现算（`js/header-fold.js` 运行时读这两个变量，脚本里不写死），需要再压矮或放高只改这两个值即可。

- `channel.html`、`detail.html` 的 `<html>` 直接带 `mast-folded`，首屏即按收窄态渲染，不会先闪全幅。内页点栏目仍在当前页跳转（本来已是收窄态，不播动画）。
- 首页点栏目：`js/header-fold.js` 先把站头高度固定为当前渲染值，再过渡到收窄高度（0.42s），动画结束后跳转。已接入新版内页的栏目链接因此改为当前页跳转，仍指向旧站的外链保持新标签打开（与内页导航规则一致）。
- 从内页点“首页”返回：`index.html` 的 `<head>` 内联脚本按来源页判断，给 `<html>` 加上 `mast-folded`（首屏即收窄，不闪全幅），`js/header-fold.js` 再展开回全幅，即“只有点首页才显示当前界面”。标志放大与主体下移在同一帧起步、同时到位。
- 展开不是高度动画（高度动画每帧都要重排重绘整页，首次回首页时正赶上首屏渲染与图片解码，会卡）。做法是：一帧内把站头摆成全幅，随即用 transform 把主导航、主体、横幅照片与标志补偿回收缩态的位置，再挂过渡把这些补偿归零 —— 全程只动 transform（合成层位移）与标志宽度，页面高度自始至终不变。主导航异步渲染撑高页面这一前提已由 `.nav-wrap` 的 `min-height` 占位消除，展开动画不再等 `site:rendered`。
- 系统开启“减弱动态效果”时不播高度过渡，直接落到对应状态。

## 2026-09-12 的三处修正

1. **站内相对链接不再被补成旧站域名**：接口给前端的站内地址是 `channel.html?id=904`／`detail.html?id=62180` 这种写法，`js/main.js` 的 `abs()` 过去只白名单 `./`、`../`、`images/`、`data:`，会把它们补成 `https://www.gxhczx.gov.cn/channel.html?id=904`（旧站没有这些页，点了打不开）。现在 `abs()` 增加 `LOCAL_PAGE` 白名单（`channel.html`／`detail.html`，有无前导斜杠都认）原样保留，`js/site-links.js` 的第二道映射仍照常把它们指向本地内页。后台填绝对地址的横幅不受影响。
2. **轮播标题被摘要裁切**：`.carousel-text` 是 flex 列，标题作为 flex 子项默认 `flex-shrink: 1`，摘要占满高度时标题被压扁，而它又有 `overflow: hidden`（≥641px 的截断块），字的下沿会被裁掉——Edge 上尤其明显。现在给 `.carousel-title` 加 `flex: 0 0 auto`，并把行高与内部 `a`／`span` 对齐到 1.4。
3. **首页字号整体加大一档**：见上文“交互与无障碍”一条；内页（`channel.html`／`detail.html`）按“首页”的字面范围未动。

## 首页区块间距：固定值、单一来源（2026-09-12 晚）

**问题**：后台把某个横幅位下线后，紧跟它后面的模块会顶上来贴住上一块——“三列模块（专委会／党派／理论）”顶到两栏主体上就是这么来的。原因不是横幅本身，而是**那段间距一直挂在横幅自己的 `margin-bottom` 上**：横幅被下线时整块 `display:none`，它的外边距也一起消失，两个模块之间就只剩 0。

**改法**：间距不再由各个模块（或横幅）自己带，改成**容器统一定的固定值**：

| 容器 | 用法 |
| --- | --- |
| `.container.page-container`（首页最外层） | 改为纵向 flex + `gap: var(--card-gap)`，子元素上下外边距一律归零（首屏 `.hero` 与导航之间的 14px 单独保留） |
| `.content-grid` 的 `.main-col`／`.side-col` | 同样是纵向 flex + `gap: var(--card-gap)`，子元素外边距归零 |
| 横幅 `.banner-single` | 上下外边距为 **0**，不再承担间距；卡内那张（`body-4`，`.card-body` 里）保持自己的卡内边距 |

这样横幅上线／下线只是**多一个或少一个 flex 项**，其余间距不变。用 `gap` 而不是给兄弟元素补 margin，还避开了一个坑：`.main-col`／`.side-col` 是 flex 列，flex 项之间的外边距**不会合并**，靠 margin 补间距会变成双倍（22+22=44）。

实测（1440 宽，本机浏览器逐项量 `getBoundingClientRect`）：

| 场景 | 首页最外层各块间距 | 两栏内部间距 |
| --- | --- | --- |
| 横幅全部在线 | 22／22／22／22／22／22／22／22（8 处） | 22×4／22×3 |
| `body-3`、`body-5` 下线（当前后台状态） | 22×8（少了一个 flex 项） | 22×3 |

390／768／1280／1440 四档视口下间距均为 22px，无横向溢出；七张横幅的计算样式上下外边距都是 `0px`。

### 撤下之后各板块怎么收（2026-09-12 晚）

后台能把三类东西“撤下”：**横幅位下线**、**内容模块下线**、**头条轮播下线**。前端的规则是——**整块收起、其余上移**，不留空白块，也不留只有标题的空框：

| 撤下的对象 | 前端表现 | 实现 |
| --- | --- | --- |
| 某个横幅位（`hero-1/2`、`body-1…5`） | 该块 `display:none`，相邻模块间距不变 | `renderBanners()` 给节点打 `hidden`；全局 `[hidden]{display:none !important}` 保证真的不占位 |
| 某个内容模块（13 个模块、7 个固定块） | **整张卡片收起**（原来会留一行“暂无更新内容”的空框） | `main.js` 的 `toggleModule()`／`fillList()`；模块数据为空即 `card.hidden = true` |
| 三列模块（专委会／党派／理论）里撤掉一两个 | 空轨道收起，剩下的自动加宽铺满整行 | `.grid-3 { grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)) }` |
| 两栏主体里整栏都空了 | 该栏收起，另一栏铺满整行（不再是 1fr + 400px 的空竖带） | `collapseEmptyBlocks()` + `.content-grid--single` |
| 头条轮播全部下线 | 收起轮播框；若首屏两条幅也下线，首屏并成一栏，领导卡铺满 | `collapseEmptyBlocks()` + `.hero--single` |
| 政协视频卡：视频列表与卡内横幅都空 | 整卡收起 | `collapseEmptyBlocks()` 里的视频卡判定 |

实测（副本库逐项把模块改成 `offline` 再刷新页面，量 `getBoundingClientRect`）：

| 撤下内容 | 结果 |
| --- | --- |
| `theory`（理论研究） | 该卡 `hidden`，剩余两张各 689px（原 452px），页面间距仍 22px |
| `theory` + `partyGroups` + `zwhWork` | `.grid-3` 整体收起（零高度容器会把 gap 撑成 44，所以必须一并隐藏），页面间距仍 22px |
| `notice`／`bookCity`／`antiGang` + `body-3` | 侧栏只剩政协视频卡；把最后一张卡也收掉后主栏由 978px 变 1400px，间距 22px |
| 6 条轮播 + `hero-1`／`hero-2` | 轮播与 `.hero-main` 收起，首屏变单栏 1400px，领导卡铺满，间距 22px |

> 另有一条后端口径随之收紧：**后台显式下线的内容不再回退到快照**。此前 `HomeRepository::blocks()` 先铺快照再逐模块覆盖，下线的模块只是跳过覆盖，快照数据又把它填回来了（表现为“后台点了下线，前台照样显示”）；现在下线的模块会从结果里删掉，头条轮播全部下线时返回空数组让前台收起轮播，只有“库里根本没配这个模块／没跑 003 迁移”时才用快照样例兜底。

## 手动刷新回顶（2026-09-11 晚，`366d7a4`／`c9096ee` 之后的修正）

需求：手动刷新（F5 / ⌘R）后回到页面顶部；浏览器前进/后退保持默认恢复；栏目页之间“点击栏目”的位置保持由 `js/channel.js` 单独负责。

**为什么“设一次 `history.scrollRestoration = "manual"`”不够**：是否恢复滚动位置由**上一份文档**决定——本页开始加载时这个决定已经做完了；而且本页开始加载后，浏览器还会在首次排版、以及内容陆续撑高的过程中反复把旧位置恢复回来。实测（Chrome 152 无头、1440 视口，本机 `python3 -m http.server`）：

| 做法 | 刷新前 1200px | 刷新前 3000px |
| --- | --- | --- |
| 什么都不做 | 停在 1200 | 停在 3000 |
| 刷新时设一次 `scrollRestoration = "manual"` 并回顶（放 `<head>` 内联与放 body 末尾结果相同） | 停在 1200 ❌ | 回到 0 ✅ |
| 改设 `scrollRestoration = "manual"` 且不区分导航类型（长期生效） | 回到 0 ✅ | 回到 0 ✅ |
| 本页现在的做法：刷新后 1.2 秒内持续压回顶部 | 回到 0 ✅ | 回到 0 ✅ |

第三种“一直关掉恢复”的做法会把前进/后退一起关掉（实测从栏目页点浏览器返回：原本停在首页 1200px，改后直接跳回顶部），与需求冲突，故不采用。

**现在 `js/site-links.js` 里的做法**：仅当本次导航类型是 `reload` 时介入，在 `DOMContentLoaded`、`load` 与随后 1.2 秒的每帧里把页面压回顶部；用户一旦自己滚动或按键（`wheel`／`touchstart`／`keydown`／`mousedown`）立即放手。前进/后退不是 `reload`，完全不介入。`index.html`／`channel.html`／`detail.html` 三页共用这一份逻辑。

**这条修正由新加的回归检查发现**：`node tests/check-pages.mjs` 首次运行即报首页刷新仍停在原位（其余 18 个用例当时全绿），详见 [../../tests/README.md](../../tests/README.md)。

## 回归与修复（2026-09-11，`b95ccf8` 已修复）

**现象**：提交 `85918c2` 上线后，`channel.html`（含 `?id=904`、`?id=202`、`?id=314`、无参数默认态）只剩“数据加载失败，请通过本地静态服务器访问本页。”，列表与分页均不渲染；`detail.html` 正文、侧栏、附件区正常，但 `document.title` 的栏目名变成 `undefined`（`标题 · undefined · 广西河池政协网`）。

**修复**：`js/shell.js` 的 `channelsReady` 改为独立请求 `data/channel.json`，精简索引只留给 `js/site-links.js` 做链接改写。内页本来就需要这份完整数据（列表、分页、栏目名），请求数不变；首页不加载 `shell.js`，首屏仍只取 4.4 KB 索引，`85918c2` 的性能收益保留。

外壳复用 `css/style.css` 的既有变量与站头样式，站级数据（`meta` / `nav` / `marquee`）统一读 `data/home.json`，不新增副本；`js/site-links.js` 生成地址映射，首页（`js/main.js`）与内页（`js/shell.js`）共用，已实现的栏目与稿件指向新内页，未覆盖的仍指向旧站。

映射数据的取法：优先读 4.4 KB 的 `data/channel-index.json`（栏目 `type` + 稿件 `id` 两个字段，足够改写链接，不会拖慢首屏）；该文件取不到时回退到 190 KB 的 `data/channel.json`。两份文件由 `tools/prototype/extract_sample_data.py` 同批生成，字段含义一致。

映射覆盖率（2026-09-11 实测，脚本统计 `data/home.json`）：210 个 `url` 字段中 184 个指向旧站，其中 95 个可改写为新版内页，89 个仍落旧站——71 个 `news_view.php` 稿件详情不在样例稿件范围内，8 个站点首页／根路径、6 个 `news-view-<id>.html` 静态页、1 个未入样例的栏目 `news_list.php?id=210`、3 个旧站专题目录。

栏目页按数据里的 `layout` 分流版式：`list`（左侧栏目按钮 + 最新新闻 + 图片新闻，右侧纯稿件列表；单栏目页隐藏栏目按钮、保留最新新闻与图片新闻左栏）、`leaders`（政协领导，按职务分组的照片卡片，见下）、`about`（一页式，列表上方加简介块）、`county`（县（区）政协，面板上方为“全部”按钮与各县区站点入口）、`gallery`（图片新闻、河池风光）、`video`（政协视频）、`topic`（专题）、`interactive`（委员直通车）；后四类为整幅卡片版式，不设左栏。

政协领导页（`channel.html?id=202`，首页一级导航名保持“政协概况”，页面标题用“政协领导”）参照湖北省政协领导页做法：按“主席 → 副主席 → 秘书长”分组，每位一张“照片 + 姓名”卡片，点照片或姓名即进入个人简介正文（`detail.html?id=<稿件ID>`）。排序与分组名单取自 `data/home.json` 的 `leaders`，不按发布时间倒序；这 10 位领导的简介正文与照片一并从旧站静态页抽取，保证点开即有内容。

左侧栏的“最新新闻”“图片新闻”由 `js/shell.js` 统一渲染，数据来源栏目页与详情页完全一致：最新新闻取各栏目稿件汇总后按发布时间倒序（排除首页聚合栏目与领导简介），图片新闻只取“图片新闻”栏目（`type=314`）中有图的稿件、按时间倒序，不会加载其它栏目的图片。详情页的正文照片固定显示宽度（领导简介 300px，其它栏目最大 700px，与参照页一致）。

**数量口径（2026-09-14）**：详情页用“detail”策略——正文短也固定 **最新新闻 10 条 + 图片新闻 2 行 4 张**；正文长时按高度往上配，**最多 15 条 + 3 行 6 张**，不往下减、不收起。栏目页仍用默认策略：图片新闻默认 2 行 4 张，可收缩为 1 行 2 张或扩展为 3 行 6 张，最新新闻在 3—30 条之间增减；内容过短时（连“3 条新闻 + 1 行图片”都放不下）隐藏整张图片新闻卡。字号缩放、窗口尺寸变化、正文图片加载完成后都会重新配平；侧栏换到主栏下方的窄屏（≤860px）不做配平。

**短稿两栏底边对齐（2026-09-14）**：配平结束后，若主栏（正文卡片）比侧栏矮，就把主栏最后一块内容撑到与侧栏同高——两栏底边齐平，多出来的空间留在卡片内（内容下方留白）；正文本身更高时不撑。每次配平前先撤掉上一轮的撑高再测量，避免“撑高→侧栏再配高→再撑高”；窄屏与打印都撤掉撑高。

### 详情页正文版式（2026-09-14，参照全国政协网稿件页）

实测参照页 `www.cppcc.gov.cn` 的稿件正文为**宋体／16px／行高 26px／首行缩进 32px（2 字）／段距 26px（一行）／图片最宽 700px／左对齐**，本页按同一口径落地：

- `.article-body` 字体走宋体族，字号 = `16px × 适老化系数 × 正文字号档位（--body-scale）`，行高与段距都用 `1.625em`（16px 下正好 26px），随字号等比缩放；
- 详情页工具栏的“正文字号”A-／默认／A+ 改为写 CSS 变量 `--body-scale`，不再直接写内联 `font-size`（否则会盖掉 16px 基准与适老化系数）；
- 元信息口径：**发布时间只到年月日**（时分不上页面）、**不显示点击／阅读数据**，来源与作者照旧；静态页模板（`backend/templates/page.php`）同步这一口径。

### 内页数据契约

`data/channel.json`（列表页）单条栏目：

| 字段 | 说明 |
| --- | --- |
| `type` / `slug` / `name` / `inner` | 旧库栏目 ID、拼音标识、一级栏目名、当前子栏目名 |
| `columnId` / `layout` | 所属一级栏目入口参数 / 版式（`list` `about` `county` `gallery` `video` `topic` `interactive`） |
| `intro` / `feature` / `counties` / `note` | 栏目简介 / 一页式栏目简介块 / 县区站点入口 / 互动栏目说明 |
| `homeSourced` | 数据取自首页模块（视频、专题、互动），不参与侧栏“最新新闻”汇总 |
| `siblings` | 同级子栏目（`type` + `name`），用于栏目切换 |
| `total` | 栏目全量条数（旧库统计值） |
| `list[]` | `{id, title, url, date, source, views, img, hasBody}`，按发布时间倒序 |

`data/article.json`（详情页）单篇：

| 字段 | 说明 |
| --- | --- |
| `id` / `channelType` / `channelName` | 文章 ID 与所属栏目 |
| `title` / `subtitle` | 主标题 / 引题副标题 |
| `date` / `source` / `author` / `editor` / `views` | 发布时间、来源、作者、编辑、阅读量 |
| `summary` / `content` | 摘要与正文 HTML。稿件编辑页的“原标题”（引题／主标题／副题）保存时已按加粗三行拼进 `content` 最前，因此详情页正文里会先出现标题块，网页标题区与首页模块不显示它 |
| `images[]` / `attachments[]` | 正文图片（2 张以上出现图集灯箱）/ 附件（有值时显示“附件下载”区） |

## 站内检索（2026-09-14 新增）

全站检索入口在首页导航下方的横栏里，表单提交到 **`search.html`**（原先直接跳旧站 `search.php`）：关键词参数 `q`、范围参数 `scope`、页码参数 `page`。

```
frontend/home/
├── search.html      检索结果页（复用内页外壳：顶栏／站头／导航／面包屑／页脚）
└── js/search.js     结果渲染、关键词高亮、分页、地址栏同步
```

- **取数**：走 `js/data-source.js` 的 `SITE_DATA.search({q, scope, page, size})`。接口模式打 `/api/v1/search`（真分页，结果自带 `excerpt` 命中片段）；静态快照模式在 `data/*.json` 里本地过一遍（43 个栏目各 24 条列表项 + 70 篇样例正文），条数标注“演示数据”，与全站条数不是一回事。
- **检索范围**：`scope=all`（默认）＝标题＋摘要＋正文，`scope=title`＝只查标题；后端排序为“标题命中优先，再按发布时间倒序”，标题命中的不会被正文命中的长尾压到几十页之后。
- **结果行**：标题（关键词高亮）＋ 发布时间 ＋ 命中片段（同样高亮）＋ 来源；片段占整行，手机端标题与日期竖排（与栏目列表同款断点）。
- **分页**：每页 20 条，页数多时只列首页、当前页前后一页与末页（与栏目页共用同一套 `pageWindow`）；翻页与提交新检索都写 `history`，地址栏出现 `page=2`，返回键能退回上一页结果。
- **旧站兜底**：结果页说明里保留“旧站全站检索”（`search.php?key=…&type=1`，含县（区）政协稿件——这部分稿件不迁新站），空结果时也引导过去。
- **样式**：表单与结果行样式在 `css/inner.css` 的“站内检索”一节；`css/style.css` 里原先那组没人引用的 `.search-form` 规则已删除，新页面用自己那套（输入框 `type="search"`、范围下拉、主色按钮）。

## 首页滚动公告（2026-09-14 起有后台入口）

首页导航条下方、搜索框左侧那条滚动要闻读 `meta.marquee`，由 `js/main.js` 的 `renderMarquee()` 渲染成两段重复文字（`translateX(-50%)` 无缝衔接，鼠标悬停暂停）。

| 后台状态 | `meta` 里的字段 | 前台表现 |
| --- | --- | --- |
| 显示中（默认） | 只有 `marquee` | 喇叭图标 + 滚动文字，搜索框靠右；文字为空时该位置显示“暂无要闻” |
| 已停用 | 多一个 `marqueeHidden: true` | 滚条整条（含图标）`hidden`，`.run-bar-inner` 加 `is-search-only`：搜索框仍贴右（右边缘与显示态同一处），宽度由 341px 放宽到 560px（`min(560px, 100%)`） |

- **横栏高度不变**：同一行里本来就是搜索框最高（桌面 40px、窄屏 36px），停用只是横向少了一块，首屏内容不会跟着上下跳。
- **窄屏（≤640px）**：横栏本来就是竖排、搜索框占满整行，停用后只是少一行。
- 入口在后台“首页管理 → 滚动公告”（`/admin/notice`）：改文字、停用／恢复都在那一页；权限沿用 `home.manage`，只改 `meta` 块里的 `marquee` 与 `marqueeHidden` 两个字段。
