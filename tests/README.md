## 前端页面回归检查（check-pages.mjs）

起一个本地服务（默认是站点与接口同源的PHP服务、临时库migrate + seed），用无头浏览器把首页、二级栏目页、详情页、检索页跑一遍，断言页面真的渲染出来了。

## 为什么要这个脚本

2026-09-11提交 `85918c2` 把站内链接映射的数据源换成4.4 KB精简索引后，`js/shell.js` 误把这份索引当栏目数据转发给 `channel.js`、`detail.js`，导致**全部栏目页打不开、详情页标题多出 `undefined`**，当天靠人工才发现（详见 [../frontend/home/README.md](../frontend/home/README.md) 的“回归与修复”一节）。这类回归的两种症状——页面出现“数据加载失败”、标题或链接里出现 `undefined`——本脚本都能自动抓到。

## 运行

```bash
cd <仓库根目录>
node tests/check-pages.mjs
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--only <关键词>` | 只跑名字含关键词的用例，如 `--only 详情`、`--only 刷新` |
| `--url <base>` | 检查已在运行的站点（如 `http://127.0.0.1:8080`），不再另起服务 |
| `--port <端口>` | 自起服务的端口，默认8973 |
| `--browser <chrome\|chromium\|msedge>` | 指定浏览器；默认先用playwright自带Chromium，版本不匹配时回退系统Chrome |
| `--static` | 改起纯静态服务器跑**快照调试模式**（用例自动带 `?api=0`）；默认不用，站点默认只走接口 |
| `--via-api` | 与默认相同（起PHP服务、站点与接口同源），保留给旧命令与“必须走接口”的断言用例 |
| `--publish` | 额外跑一遍 `backend/bin/publish.php`（输出到临时目录），用静态服务检查**发布产物**的正文排版与资源地址 |
| `--headed` | 显示浏览器窗口，便于肉眼对照 |
| `--keep` | 检查结束后保留静态服务器（排查问题时用） |

退出码：全部通过为 `0`，有用例失败为 `1`，脚本自身出错为 `2`。

## 依赖

- Node 18以上（本机v26）。
- playwright库：先找项目内 `node_modules`，再找全局 `npm root -g` 下的 `@playwright/cli/node_modules/playwright`。本机已通过全局 `@playwright/cli` 提供，无需额外安装。
- 浏览器：优先playwright自带Chromium；本机缓存里的版本与驱动不匹配时会自动回退到系统Google Chrome（`channel=chrome`）。
- `python3`：与仓库README的本地预览方式一致，用 `python3 -m http.server` 起静态服务。

> 页面数据来自 `fetch` 本地JSON，必须经静态服务器访问；直接双击HTML文件会失败。

## 检查项

每个用例都会断言：

1. 页面返回200，且首屏关键容器已经渲染出来（等 `ready` 选择器出现再判分）。
2. 文档标题与正文不出现 `undefined`，不出现“数据加载失败”，详情页标题不残留“信息加载中”，`href`／`src` 里不出现 `undefined`。
3. 没有横向溢出（`scrollWidth - clientWidth ≤ 1px`）。
4. 没有破图（已加载完成但 `naturalWidth === 0`；未触发的懒加载不计入）。
5. 无JS异常、无控制台error、无本地请求失败（4xx／5xx）。
6. 用例指定的容器数量下限、必须可见的区块、必须出现或不许出现的文案。

另有两类专项用例：

- **分页**：点栏目页第2页，列表仍有内容且页码文案同步。
- **分页（2026-09-12起）**：栏目页列表走 `/api/v1/articles` 真分页（每页20条），接口不可用时用快照本地分页；`api-check.mjs` 另外断言栏目 `total` 与稿件分页接口的 `total` 一致、且是实时公开条数（不再是快照常量）。
- **刷新回顶**：先把页面滚到1200px，再 `reload`，断言回到顶部（`scrollY ≤ 50`）。这条对应提交 `366d7a4`、`c9096ee` 的行为。
- **详情页正文排版（2026-09-14新增）**：断言正文没有空段、没有自带首部空格（与2字缩进叠加）、正文为宋体族且行高1.625字、段间距约一行（参照全国政协网稿件页）、首个可见字符距版心约2字、正文已有图时图集条不再重复渲染、标题上方只有一行标题、发布时间只到年月日且不出现阅读数据。
- **详情页侧栏与底边对齐（2026-09-14新增）**：侧栏最新新闻10–15条、图片新闻4–6张（短稿固定10条 + 4张，长稿顶到15条 + 6张）；短稿时正文卡片撑到与侧栏同高、两栏底边对齐（内容下方留白）；点A+ 后正文字号变大。
- **正文题区（2026-09-14新增）**：`title-zone` 用例断言题区按行留在正文——两行题区（引题＋主标题）即使引题与标题相同也保留（61598、63904），单行且与标题一字不差的重复标题不再出现在正文首行（154）。
- **长文右栏 / 回到顶部 / 打印（2026-09-14新增）**：右栏高于视口时取消 `position: sticky`；滚动后出现“回到顶部”且点击能回到顶部；`emulateMedia({media:'print'})` 下站头、导航、面包屑、侧栏、工具栏、页脚都不可见。
- **发布产物（2026-09-14新增，`--publish`）**：临时发布一次，直接检查 `article/<id>.html`：正文排版与接口同口径、不再出现 `http://gxhczx.gov.cn` 明文地址、视频不超出正文宽度。

## 已知限制

- 样例数据只有每栏目24条，列表分页只在样例范围内生效；全量数据接入后需同步调整预期条数。
- 检查的是渲染结果、运行时报错与可量化的排版指标（段距、首行缩进、横向溢出、打印态隐藏），配色、字体观感这类仍需肉眼看截图。
- 详情页排版用例只在接口可用时断言：接口不可用时前端回退的是阶段A原型快照（`frontend/home/data/article.json`），那份数据不经过后端出口归一化，不在本用例口径内。
- 站内搜索仍指向旧站 `search.php`，脚本不对其断言。

## 后端接口对拍（api-check.mjs）

把后端接口的返回与阶段A的静态快照（`frontend/home/data/`）逐项比对。做三件事：

1. 用**临时SQLite库**跑 `backend/bin/migrate.php` + `backend/bin/seed.php`（不动开发库）；
2. 起PHP内置服务器，逐个打接口，比对字段、顺序、分页与错误码；
3. 跑一遍静态化发布，检查数据快照、静态页与sitemap的结构。

```bash
node tests/api-check.mjs                                  # 全自动（需要本机有 php）
node tests/api-check.mjs --url http://127.0.0.1:8080      # 只检查已在跑的服务
node tests/api-check.mjs --keep                           # 保留临时库与发布产物便于排查
```

### 对拍中发现并修正的三个建模问题

1. **一篇稿件可同时挂在多个栏目**：县区动态同时进“县区政协工作动态”（906）与“县（区）政协”（qy），原先按 `cms_article.channel_type` 单栏目录入，906会变成空列表。改为 `cms_article_channel` 归属表承载。
2. **视频、专题栏目的内容来自首页模块**：它们的列表项id是 `316-1` 这类原型合成值，不是旧库稿件号，不能进 `cms_article`；改由接口按 `home_sourced` 标识从 `cms_home_block` 现算。

- **批量重置密码**：没勾选时被挡下；勾选两个账号后提示下载一次性清单，两人密码互不相同，第二次下载取不到、页面也不再提示。
