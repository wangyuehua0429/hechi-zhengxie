## 前端页面回归检查（check-pages.mjs）

起一个本地静态服务器，用无头浏览器把首页、二级栏目页、详情页跑一遍，断言页面真的渲染出来了。

## 为什么要这个脚本

2026-09-11 提交 `85918c2` 把站内链接映射的数据源换成 4.4 KB 精简索引后，`js/shell.js` 误把这份索引当栏目数据转发给 `channel.js`、`detail.js`，导致**全部栏目页打不开、详情页标题多出 `undefined`**，当天靠人工才发现（详见 [../frontend/home/README.md](../frontend/home/README.md) 的“回归与修复”一节）。这类回归的两种症状——页面出现“数据加载失败”、标题或链接里出现 `undefined`——本脚本都能自动抓到。

## 运行

```bash
cd <仓库根目录>
node tests/check-pages.mjs
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--only <关键词>` | 只跑名字含关键词的用例，如 `--only 详情`、`--only 刷新` |
| `--url <base>` | 检查已在运行的站点（如 `http://127.0.0.1:8899`、GitHub Pages 地址），不再另起静态服务器 |
| `--port <端口>` | 自起静态服务器的端口，默认 8973 |
| `--browser <chrome\|chromium\|msedge>` | 指定浏览器；默认先用 playwright 自带 Chromium，版本不匹配时回退系统 Chrome |
| `--via-api` | 起 PHP 服务（站点与接口同源）跑同一批用例，并断言页面取数走的是接口而非静态快照 |
| `--publish` | 额外跑一遍 `backend/bin/publish.php`（输出到临时目录），用静态服务检查**发布产物**的正文排版与资源地址 |
| `--headed` | 显示浏览器窗口，便于肉眼对照 |
| `--keep` | 检查结束后保留静态服务器（排查问题时用） |

退出码：全部通过为 `0`，有用例失败为 `1`，脚本自身出错为 `2`。

## 依赖

- Node 18 以上（本机 v26）。
- playwright 库：先找项目内 `node_modules`，再找全局 `npm root -g` 下的 `@playwright/cli/node_modules/playwright`。本机已通过全局 `@playwright/cli` 提供，无需额外安装。
- 浏览器：优先 playwright 自带 Chromium；本机缓存里的版本与驱动不匹配时会自动回退到系统 Google Chrome（`channel=chrome`）。
- `python3`：与仓库 README 的本地预览方式一致，用 `python3 -m http.server` 起静态服务。

> 页面数据来自 `fetch` 本地 JSON，必须经静态服务器访问；直接双击 HTML 文件会失败。

## 检查项

每个用例都会断言：

1. 页面返回 200，且首屏关键容器已经渲染出来（等 `ready` 选择器出现再判分）。
2. 文档标题与正文不出现 `undefined`，不出现“数据加载失败”，详情页标题不残留“信息加载中”，`href`／`src` 里不出现 `undefined`。
3. 没有横向溢出（`scrollWidth - clientWidth ≤ 1px`）。
4. 没有破图（已加载完成但 `naturalWidth === 0`；未触发的懒加载不计入）。
5. 无 JS 异常、无控制台 error、无本地请求失败（4xx／5xx）。
6. 用例指定的容器数量下限、必须可见的区块、必须出现或不许出现的文案。

另有两类专项用例：

- **分页**：点栏目页第 2 页，列表仍有内容且页码文案同步。
- **分页（2026-09-12 起）**：栏目页列表走 `/api/v1/articles` 真分页（每页 20 条），接口不可用时用快照本地分页；`api-check.mjs` 另外断言栏目 `total` 与稿件分页接口的 `total` 一致、且是实时公开条数（不再是快照常量）。
- **刷新回顶**：先把页面滚到 1200px，再 `reload`，断言回到顶部（`scrollY ≤ 50`）。这条对应提交 `366d7a4`、`c9096ee` 的行为。
- **详情页正文排版（2026-09-14 新增）**：断言正文没有空段、没有自带首部空格（与 2 字缩进叠加）、正文为宋体族且行高 1.625 字、段间距约一行（参照全国政协网稿件页）、首个可见字符距版心约 2 字、正文已有图时图集条不再重复渲染、标题上方只有一行标题、发布时间只到年月日且不出现阅读数据。
- **详情页侧栏与底边对齐（2026-09-14 新增）**：侧栏最新新闻 10–15 条、图片新闻 4–6 张（短稿固定 10 条 + 4 张，长稿顶到 15 条 + 6 张）；短稿时正文卡片撑到与侧栏同高、两栏底边对齐（内容下方留白）；点 A+ 后正文字号变大。
- **正文题区（2026-09-14 新增）**：`title-zone` 用例断言题区按行留在正文——两行题区（引题＋主标题）即使引题与标题相同也保留（61598、63904），单行且与标题一字不差的重复标题不再出现在正文首行（154）。
- **长文右栏 / 回到顶部 / 打印（2026-09-14 新增）**：右栏高于视口时取消 `position: sticky`；滚动后出现“回到顶部”且点击能回到顶部；`emulateMedia({media:'print'})` 下站头、导航、面包屑、侧栏、工具栏、页脚都不可见。
- **发布产物（2026-09-14 新增，`--publish`）**：临时发布一次，直接检查 `article/<id>.html`：正文排版与接口同口径、不再出现 `http://gxhczx.gov.cn` 明文地址、视频不超出正文宽度。

### 用例与数据源的关系

同一篇稿件的预期会随数据源变化，脚本按目标实际情况选用例：

| 标记 | 何时跑 | 例子 |
| --- | --- | --- |
| 通用 | 任何目标 | 首页、栏目页、详情页常规与手机端、刷新回顶 |
| `seededData` | 预期基于阶段 A 快照数据（静态目标、`--via-api` 临时库） | 附件下载（40029）、正文未内置（62212） |
| `onlyApi` | 只在脚本自建临时库时（`--via-api` 且未指定 `--url`） | 草稿不对外可见（脚本会把 62245 改成草稿） |
| `apiData` | 目标接口可用时（归一化发生在后端出口） | 详情页正文排版（62180） |
| `devOnly` | 目标接口可用、且不是自建临时库（即指向开发库） | 引题与标题相同仍保留（63904）、单行重复标题去重（154） |

## 已知限制

- 样例数据只有每栏目 24 条，列表分页只在样例范围内生效；全量数据接入后需同步调整预期条数。
- 检查的是渲染结果、运行时报错与可量化的排版指标（段距、首行缩进、横向溢出、打印态隐藏），配色、字体观感这类仍需肉眼看截图。
- 详情页排版用例只在接口可用时断言：接口不可用时前端回退的是阶段 A 原型快照（`frontend/home/data/article.json`），那份数据不经过后端出口归一化，不在本用例口径内。
- 站内搜索仍指向旧站 `search.php`，脚本不对其断言。

### 两种数据源都要跑

```bash
node tests/check-pages.mjs              # 静态模式 19 例：验证 GitHub Pages 等纯静态托管可用
node tests/check-pages.mjs --via-api    # 接口模式 20 例：临时库 + PHP 服务，验证前端走 /api/v1
```

接口模式会额外把一篇已发布稿件改成草稿，验证“草稿不对外可见”，并逐例断言 `window.SITE_DATA.mode() === "api"`（防止页面悄悄回退到静态快照而检查看不出来）。

## 后端接口对拍（api-check.mjs）

把后端接口的返回与阶段 A 的静态快照（`frontend/home/data/`）逐项比对。做三件事：

1. 用**临时 SQLite 库**跑 `backend/bin/migrate.php` + `backend/bin/seed.php`（不动开发库）；
2. 起 PHP 内置服务器，逐个打接口，比对字段、顺序、分页与错误码；
3. 跑一遍静态化发布，检查数据快照、静态页与 sitemap 的结构。

```bash
node tests/api-check.mjs                                  # 全自动（需要本机有 php）
node tests/api-check.mjs --url http://127.0.0.1:8080      # 只检查已在跑的服务
node tests/api-check.mjs --keep                           # 保留临时库与发布产物便于排查
```

覆盖的 55 项检查包括：探活、43 个栏目的数量与栏目号集合、**栏目顺序与快照一致（即前台主导航顺序）**、**每个栏目的列表项顺序与快照逐项一致**、单栏目元信息与列表、列表项字段（`date`／`datetime`／`views`／`hasBody`）、`/articles` 分页结构与 size 上限、详情页字段与正文图片、附件（两种写法结果一致）、检索（命中、缺参数报错、`scope=title` 只查标题且命中数不多于默认范围、结果带 `excerpt` 命中片段、标题命中的排在正文命中的前面、`%` 按字面量处理、非法 `scope` 报 400）、首页覆盖快照全部模块并多出 `banners`、`slides` 来自新表、7 个横幅槽位齐全、未知栏目／未知稿件／未知路径的 404 错误体，以及发布器的数据快照、精简索引、详情静态页与 sitemap。

### 对拍中发现并修正的三个建模问题

1. **一篇稿件可同时挂在多个栏目**：县区动态同时进“县区政协工作动态”（906）与“县（区）政协”（qy），原先按 `cms_article.channel_type` 单栏目录入，906 会变成空列表。改为 `cms_article_channel` 归属表承载。
2. **视频、专题栏目的内容来自首页模块**：它们的列表项 id 是 `316-1` 这类原型合成值，不是旧库稿件号，不能进 `cms_article`；改由接口按 `home_sourced` 标识从 `cms_home_block` 现算。
3. **详情页的 `channelName` 取子栏目名**（`sys_channel.inner_name`），与 `article.json` 一致；另把栏目 `listSize` 默认值从 24 提到 50，否则“公告通知”40 条会被截断。

## 后台管理界面检查（admin-check.mjs）

### 排序端到端（order-e2e.mjs）

排序这件事横跨“后台页面 → 数据库 → 接口 → 前台”，所以单独一个脚本把整条链路串起来跑，输出每一步的前后顺序，便于肉眼核对：

```bash
node tests/order-e2e.mjs          # 19 项：四类排序 + 还原
node tests/order-e2e.mjs --keep   # 保留临时库与临时服务产物
```

- **B 首页导航顺序**：`/admin/nav` 上移第 3 项 → `/api/v1/home` 的 `nav` 顺序同步（首页与内页顶栏同源）；再还原。
- **C 头条轮换顺序**：`/admin/slides` 上移第 2 条 → 首页 `slides` 顺序同步；再还原。
- **D 栏目内稿件顺序**：按单栏目筛选的稿件列表上用 ↑↓ → 栏目接口与首页“政协动态·市政协动态”同时变化；再还原。
- **E 按栏目置顶**：列表／首页管理里的置顶按钮（编辑表单不再设置排序）→ 栏目列表与首页模块同时排最前；取消置顶后**按发布时间落回原位**，不会把旧稿顶到最前。
